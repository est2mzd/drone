# D12 整合を取り直した地図と統合結果

図の対応：DFD（Data Flow Diagram、データの流れを示す図）の「整合を取り直した地図・統合結果」と「地図・キーフレーム」。接続は **P03 ↔ D10 → P01/A23**。純単眼の補正・統合が、共有する地図のどの情報を更新するかを扱う。

## 結果は姿勢や点だけではない

再訪した場所の対応が確認されると、それまで蓄積した姿勢・点のずれを見直す材料が得られる。別々に作った地図どうしの対応なら、座標を合わせて観測関係を結ぶ必要もある。候補探索や成立判定はP03で扱い、本章では受け入れた対応に基づく結果の書戻しを見る。

入力は補正・統合対象の地図、確認された対応、推定した変換などである。出力は、新しいファイル一つというより、Atlas内の既存オブジェクトの姿勢・位置・関連が更新された状態である。後続のTrackingや保存処理が、その共有情報を読み出す。

| 更新される情報 | 結果として変わること |
| --- | --- |
| KeyFrame（キーフレーム、以下KF）の姿勢 | 世界→カメラの変換が補正される。新しい画像時刻を付け直す操作ではない |
| MapPoint（地図点、以下MP）の位置 | 補正された姿勢・座標関係に沿って位置を更新し、方向・距離情報も更新する |
| 特徴とMPの対応 | 同じ場所に重複した点の置換、観測追加・解除などで対応先が変わる |
| KF間の接続 | 共視関係を更新し、ループや統合の接続、必要な木の接続を追加・修正する |
| Map所属とAtlas管理 | 別Map統合ではKF/MPの所属、各Mapの登録集合、current/badの管理も変わる |

点の融合は、座標配列を単純に連結することではない。D11の`Replace`などを通じて、どの特徴がどの点を観測したかも整理する。したがって、位置が変わらない一つのKFや点だけを見ても、補正結果の全体は分からない。

## 同Mapのループ補正と別Mapの統合

| 経路 | 結果の主な違い |
| --- | --- |
| `CorrectLoop` | 同じMap内でKF姿勢・点位置を補正し、重複点を融合、共視・loop接続を更新する。Map実体を新設する処理ではない |
| `MergeLocal` | 一方の窓の姿勢・点を統合先の座標へ合わせ、KF/MPの所属を移す。currentを切り替え、残りの姿勢・点・所属も処理してmerge接続を追加する |

別Mapの統合を、仮名A・Bの二つの**Mapオブジェクト**で考える。Aが旧current、Bが統合先なら、A側の対象KF/MPはB側の座標と所属へ移され、Bがcurrentになる。Aはbadにされ通常Map集合から外れる。A/Bは数値IDの別名ではなく、オブジェクトを区別する説明用の名前である。

現行はこの途中で、生存する統合先MapのID（Identifier、識別番号）を旧currentのIDへ変更する箇所もある。そのため、数値IDが同じか違うかだけで、どのMap実体が残ったかを説明しない。別Mapを空のまま新設するA20とは異なる処理である。

通常集合から外すのは`SetMapBad`であり、後段の`RemoveBadMaps`はbad管理集合を空にする処理である。後者のdeleteループはコメントアウトされている。通常集合からの除去、bad管理集合のクリア、実体のメモリ解放を同じ段階として扱わない。

## 点を補正した座標へ戻す最小式

あるKFを基準に点の補正を伝える部分は、旧姿勢で一度カメラ側へ写し、新しい補正変換の逆で地図側へ戻す、と読める。P03の相似変換を使った整理式は次のとおりである。

\[
X_{w,\mathrm{new}}
 = S_{iw,\mathrm{new}}^{-1}\!\left(S_{iw,\mathrm{old}}(X_{w,\mathrm{old}})\right),
\qquad S(X)=sRX+t.
\]

| 記号 | 型・座標・単位・前提 |
| --- | --- |
| \(X_{w,\mathrm{old}},X_{w,\mathrm{new}}\) | 同じ点の補正前・後の地図座標を表す三成分の実数列ベクトル。old/newは前後の目印 |
| \(i,w\) | iは補正を伝えるKF、wは地図の世界座標を区別する添字 |
| \(S_{iw,\mathrm{old}},S_{iw,\mathrm{new}}\) | 各時点の地図座標から共通の中間カメラ座標への、可逆な三次元相似変換 |
| \(S^{-1}\) | Sの逆変換。式は内側の旧変換を先に適用し、その結果へ新変換の逆を適用する |
| \(X,S,R,s,t\) | 一般形の入力三成分ベクトル、変換、3×3回転、正の尺度比、出力側の三成分並進 |
| 回転・尺度の前提 | Rは正規直交・行列式＋1、s＞0。Rとsは無次元 |

位置と並進は対応する座標系の長さ単位であり、純単眼では地図の任意尺度である。中間座標の規約をそろえた変換を合成する前提で、メートル尺度を自動獲得する式ではない。またSは尺度付きの補正変換であり、KFに保存する剛体姿勢そのものとは区別する。姿勢保存時の並進と尺度の扱いはP03を参照する。

仮に旧変換が`S_old(X)=X`、新変換が`S_new(X)=2X`なら、旧点`(2,0,6)`は新点`(1,0,3)`へ更新される。新点を新変換で写すと、旧点を旧変換で写した中間座標`(2,0,6)`と一致する。回転なし・並進ゼロ・尺度だけを変えた仮定例で、実データの補正量や誤差改善を示す値ではない。

この式は点の補正を伝える一段階を説明する。地図全体に常に一つの同じ変換を適用する、あるいは後続の最適化が点をもう変更しない、という保証にはしない。

## Trackingは更新をどう読むか

| 現行の接続 | 読み取れる意味 |
| --- | --- |
| Mapの変更番号の比較 | Trackingは取得したcurrent Mapの更新mutex下で番号を比較し、変更を検知する |
| `CheckReplacedInLastFrame` | 通常OK経路で、前Frameが指す点に置換先があれば、その参照へ差し替える |
| `UpdateLastFrame` | 運動モデル経路で、参照KFの現在姿勢と保持する相対関係から前Frame姿勢を再構成する |

これらは共有地図を後続処理へ反映する接点である。変更フラグを検知しただけで、全センサ・全画像の姿勢を一括再予測するという説明ではない。必要な経路で新しいKF姿勢やMP参照を読むことと、地図全体の更新が一時点に完了していることを分ける。

参照KFを介して前Frameを再構成する関係はA09を、地図の共有とロック範囲はD10を参照する。wrapperへ過去に返した姿勢値の独立コピーまで、共有地図と同時に自動書換えされるという意味でもない。

## 「補正結果」と完了・保存の境界

純単眼の同Mapループ補正には姿勢グラフの最適化がある。一方、別Map統合の後半の`OptimizeEssentialGraph`は`MONOCULAR`では分岐外である。論文の手順を一律に当てはめず、結果の生成経路の違いはP03に従う。

必要に応じた全体バンドル調整（Global Bundle Adjustment、GBA）は非同期の処理で、起動・再起動や中断・結果採用には条件がある。ここで「補正された」と表現するのは、対応するデータ更新が行われたことを指す。全最適化の完了・収束や真値一致を意味しない。条件の詳細はP03を参照する。

読み出したMap/KF/MPの参照一覧は実体の固定コピーではなく、終了時の`Shutdown`も現行では終了待ちブロックがコメントアウトされている。A23の独自出力まで進んだことから、二出力が常に同じ時点の原子的スナップショットであるとは保証できない。実際の不整合を再現したとの主張でもない。

## 理解確認

1. 補正結果として、KF姿勢・MP位置以外に何が変わるか。
2. 別Map統合で、生存Mapの数値IDが不変だと仮定できるか。
3. 補正結果が共有地図に反映されたことは、全最適化や一貫した保存の完了を意味するか。

答えの要点：観測対応・接続・必要時のMap所属／現行にはID変更がある／データ反映と各完了保証は別である。
