# O04 object_mapの別系統の観測実験

図の対応：境界図の「object_map：物体検出・深度・平面の観測実験」。接続は **D01 → 観測候補**。現行コードでは、ここで作った候補をORB-SLAM3の内部地図やpatrolへ直接登録する接続は確認されない。

## 検出枠と深度を照らし合わせる目的

画像の検出器が「椅子」と名付けた枠の中には、背景や別の物体も含まれ得る。`object_map`は、検出枠の内側で予測深度がどの程度まとまるかを調べ、追加の観測情報を保存する実験である。さらに、平面らしい領域や薄い形状との関係を比較する。

これは保存動画を標本抽出して行う別プログラムであり、SLAM（Simultaneous Localization and Mapping、自己位置推定と地図作成）の地図更新そのものではない。検出クラス、深度のまとまり、平面らしさは、それぞれ異なる観測である。

| 入口 | 入力と処理 | 主な出力 |
| --- | --- | --- |
| `extract_objects.py` | 保存動画から画像を抽出し、検出枠と深度を照合 | 画像ごとのYAML、重ね画像JPG、`summary.yaml` |
| `verify_papers.py` | 同様の画像・予測深度から点と平面候補を作り、枠との関係を比較 | 比較画像、平面・領域の条件や件数の集計 |
| `render_review_video.py` | 検出・深度・平面処理を再利用して標本画像を比較表示 | 四面の比較動画、深度の滑らかさ・第二の深度集団などの統計 |

YAML（YAML Ain't Markup Language）は名前付きの値を保存するテキスト形式である。基本出力には動画の参照、画像番号・寸法、時刻、検出クラスとscore、枠、相対深度の統計、画素上の重心などを記録する。世界姿勢Tcwや世界座標、実寸は含めない。

`extract_objects`の標本数は既定で一本につき2画像である。時刻を作る枝では画像番号/FPS（Frames Per Second、秒当たりの画像枚数）を使い、機体の撮像時計を測る処理ではない。これらの出力は毎画像の連続追跡記録とも、異なる実物体を重複なく数えた一覧とも限らない。

## 実際に使う二つのモデル

検出はUltralyticsの`YOLO`へローカル名`yolo11n.pt`を渡す構成で、画像サイズ640、score下限0.25を指定する。YOLOはYou Only Look Onceの略称で、ここではYOLO11の物体検出モデルを使う。公式資料ではCOCO（Common Objects in Context）事前学習のDetection用ファイルに対応するが、今回ローカル重みの内容・ハッシュを検査したわけではない。

コードが読むのは`boxes.xyxy`、クラス番号、confidenceから得る矩形・クラス名・scoreである。検出枠は物体の正解輪郭マスクではなく、scoreも深度精度やクラスの正しさを実測した値ではない。

深度はDA3（Depth Anything 3）の`depth-anything/DA3-SMALL`を指定する。公式モデルカードは相対深度モデルとして説明している。現行コードは単画像を一枚のリストとして渡し、処理解像度504を指定して、`prediction.depth[0]`だけを使う。寸法が元画像と違えば線形補間で戻す。

この呼出しは校正Kや保存Tcwを渡さず、モデルが返し得る姿勢や信頼度も利用しない。コードにはCPU（Central Processing Unit、中央処理装置）へ配置する指定があるが、今回モデルを取得・ロード・実行してはいない。

出力の`depth_unit`は`relative`である。数値をメートルへ校正した処理ではなく、別画像間の尺度がそろうこともこの単画像処理から保証しない。モデル論文が複数画像や三次元幾何を扱うことと、手元でその機能を全て利用していることを分ける。

## 「深度がそろう」の具体的な判定

枠の縁を避けるため内側領域を作る。`BBOX_SHRINK=0.10`だが、実装は幅・高さの10%を両側へ半分ずつ配分するため、丸め・画像端処理前には**各側5%**ずつ縮める。各側10%というコメントの読み方は現行演算と一致しない。

領域内の有限で1e-6より大きい深度だけを有効とする。深度を小さい順に並べ、相対的な幅の条件を満たす区間のうち、画素数が最大の区間を探す。平面や連続した画像領域を探す処理ではなく、まず深度値の分布を調べる処理である。

有効画素集合をV、その最多区間に入る画素集合をS、許容値をrとすれば、コードの条件を次のように整理できる。

\[
\frac{z_{\max}}{z_{\min}}\le\frac{1+r}{1-r},\qquad
a=\frac{|S|}{|V|}.
\]

zは各画素の正の予測深度の数値で、zmin・zmaxは選んだ区間の最小・最大である。深度の計量単位は未確定だが比は無次元。rは0より大きく1未満の無次元値で、採用判定では0.15。縦棒は集合の画素数、aは無次元の一致比率である。式はVが空でない場合に使い、空ならコードは比率0・代表深度なしを返す。

実装は対数深度の幅`log((1+r)/(1-r))`を用いる。代表深度は選んだ対数値の中央値を指数で戻すため、偶数個では中央二値の幾何平均となる。**返した代表深度を中心に全採用点が±15%以内にある、という判定ではない。**

`accepted`は、内側の面積が400画素以上、代表深度が存在し、aが0.50以上ならtrueになる。分母は内側領域の全画素数ではない。例えば面積500画素、有効深度10画素、最多区間がそのうち6画素という仮定ならa=0.6となり、これらの条件を通過する。深度の欠けた490画素を含めて60%が一致したという意味ではない。

複数の許容値での比率や連結成分数も記録するが、成分が一個であることを採用条件にはしていない。`dynamic`も特定クラス名に付ける印で、動きを画像間で測った結果ではなく、現行`accepted`から動的クラスを除外する分岐もない。

従ってacceptedは、この深度分布条件を通ったという意味である。クラスが正しい、同一物体の全表面が取れた、静止している、実寸が分かった、という証明にはならない。

## 平面候補はカメラ座標の近似から作る

`verify_papers`は予測深度をカメラの光軸方向zとして使い、標本画素を三次元へ戻す。特定の保存動画名に一致し校正ファイルもある場合は、校正の焦点距離・主点を画像寸法比で拡縮する。それ以外は焦点距離を両軸とも画像幅の0.9倍、主点を画像中央と仮定する。歪み補正は行わない。

以下はその近似演算を表す式であり、予測深度・校正・レンズ歪みが実測で整合したと主張するものではない。

\[
X_c=z\begin{pmatrix}(u-c_x)/f_x\\(v-c_y)/f_y\\1\end{pmatrix},\qquad
n^{\mathsf T}X_c+d=0,\qquad
\delta=\left|n^{\mathsf T}X_c+d\right|.
\]

| 記号 | 型・単位・座標・前提 |
| --- | --- |
| \(u,v\) | 標本画素の横・縦座標、pixel。画像の右・下を正とする |
| \(f_x,f_y,c_x,c_y\) | 焦点距離と主点の実数値、pixel。焦点距離は正と仮定 |
| \(z,X_c\) | zは前方深度として利用する正の相対値。Xcは三成分のカメラ点で、右・下・前方を正とし、zと同じ相対単位 |
| \(n,d\) | nは三成分・無次元・長さ1の平面法線。dは平面のoffsetで、Xcと同じ相対単位 |
| \(\delta,\mathsf T\) | δは近似点から平面への距離、相対単位。上付きTは転置。ここでの縦棒はスカラーの絶対値 |

画素は縦横4画素間隔で取り、有効深度から最大6000点を選ぶ。3点から平面仮説を作るRANSAC（Random Sample Consensus、外れ値を含む点から仮説を試す方法）により、距離が閾値未満となる点が多い平面を選ぶ。閾値はその点群の深度中央値に比例させ、採用点を除きながら最大3平面を得る。

このXcに保存姿勢を掛けて世界へ配置する処理はない。単画像の相対深度に、仮の内部パラメータや未補正の歪みが加わる場合があるため、平面の寸法・向きの真値誤差は別に測る必要がある。

## 支持面・構造面というラベルの範囲

`support`は平面法線が固定ベクトル`(0,-1,0)`に平行に近いかを、符号を無視した角度10度以下で判定する。このベクトルはカメラ座標の上方向の仮定であり、実測した重力方向ではない。「水平面が存在しない」「床を発見した」という世界座標の断定へ広げない。

`structure`は、縦横4画素間隔の有効深度標本に対する平面内比率が0.12以上という条件である。全画像画素の12%という分母ではない。枠内の深度集団と平面の重なり、三次元点の厚み比なども比較するが、それだけで壁・家具・物体クラスの正解は確定しない。

`verify_papers`にQuadricSLAM、CubeSLAM、Kimera等の研究名が現れても、このコードは各論文の最適化器を実行するものではない。ローカルに定めた観測条件の比較であり、原算法全体を再現した性能評価と解釈しない。

保存用の`public_frame`では、平面の角度、coverage、support、structureを出力する。内部で計算した法線・offset自体は、その平面一覧へ保存しない。集計と画像があることを、後段で使える世界平面地図の完成とはしない。

## 可視化と外部システムへの境界

四面動画は、検出枠・深度一致・支持面候補・広い平面候補を見比べるために作る。標本画像を繰り返して出力し、滑らかさや別の深度集団も集計するが、世界座標の地図を時間方向へ蓄積しているわけではない。

読んだ三スクリプトと、patrol・SLAM wrapper・ORB-SLAM3の必要なコードを検索した範囲では、これらの観測をAtlasや巡回用Worldへ登録・利用する直接接続は見つからない。「あとで同じ観測を使う」というコメントは、現在の接続実装の証拠とは分ける。

深度がまとまる領域も平面候補も、実寸の障害物や通行可能空間の保証ではない。特に観測がない場所を空き空間として扱う処理はこの実験からは導けない。既存の調査報告の件数や速度、候補の解釈は過去の記録であり、今回の再測定や真値として継承していない。

## 理解確認

1. acceptedの比率は何を分母にするか。動的クラスや複数の連結成分は自動除外されるか。
2. 予測深度をZとして逆投影するとき、尺度・校正・上方向にはどんな前提があるか。
3. 平面候補と比較動画が得られれば、ORB地図や巡回地図への統合も済んでいるか。

答えの要点：有限で正の有効深度画素、どちらもその理由だけでは除外しない／相対尺度・近似K・未補正歪み・カメラ上の仮定／直接統合は現行で確認されず、観測候補の実験までである。
