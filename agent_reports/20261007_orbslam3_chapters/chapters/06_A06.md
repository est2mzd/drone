# A06 二視点からの初期地図作成

## 図の位置、背景と目的

図Aの **[複数画像から初期地図を作る]** に対応する。A05の「いいえ」から入り、A07の成立判定へ進む。ここで作る初期KeyFrame・MapPoint・観測関係は、D09/D10/D11のデータになる。

一枚の画像の目印は、カメラから見た方向を示しても、奥行きを一つに決められない。同じ目印を別の位置から見ると、二つの視線の関係から奥行きを求められる。ただし開始時はカメラの移動も未知なので、対応点から**二視点の相対姿勢と地図を一緒に作る**必要がある。

本章の目的は、その出発点を作る手順と座標の意味を理解すること。対象は手元の純単眼・ピンホール構成で、慣性センサによる実寸尺度の推定は含まない。成立個数などの詳しい判定はA07に分ける。

## 入出力と手順

| 入出力 | 内容 |
| --- | --- |
| 入力 | 保持した初期候補Frameと後続Frameの特徴・記述子、カメラ校正。必ずしも動画の最初の連続2枚ではない |
| 相対姿勢の候補 | 第1カメラから第2カメラへの回転と並進。並進の実寸は未知 |
| 成立時に目指す出力 | 2枚のKeyFrame、3次元MapPoint、両画像での観測関係、調整した姿勢と地図 |

Frameは一枚の画像情報、KeyFrameは地図作成用に残す重要画像、MapPointは3次元地図点である。出力を作る設計上の流れは次のとおり。手元のH経路には点群の受け渡しに懸念があり、後述する。

```text
初期候補画像を保持 → 後の画像と特徴を対応付ける
 → H/Fの二つの幾何モデルを求めて一つを選ぶ
 → 回転・並進候補ごとに点を三角測量し、整合を調べる
 → 採用対応から2 KeyFrameとMapPointを作る
 → 初期BA → 深度中央値による尺度調整 → A07へ接続
```

## 理論1：対応点を二つのモデルで説明する

ORB（Oriented FAST and Rotated BRIEF：画像の目印を検出し見た目を記述する方式）の記述子で、同じものらしい特徴を対応付ける。見た目の近さだけでは誤対応を除けないため、複数の対応が同じ幾何関係を満たすかも調べる。

平面状の場面などで対応を説明する**ホモグラフィ（Homography）H**と、一般の二視点の対応を制約する**基礎行列（Fundamental matrix）F**を並列に推定する。RANSAC（Random Sample Consensus：一部の対応から候補を作り、多くの対応との一致を検証する方法）により、誤対応の混入を考慮して候補を探す。[原論文PDF6頁、誌面5頁、§IV][orb-slam]

次は理想的な対応に対するモデル式である。実データではこの関係からのずれを評価する。

\[
\widetilde{\mathbf u}_2\sim H_{21}\widetilde{\mathbf u}_1,\qquad
\widetilde{\mathbf u}_2^T F_{21}\widetilde{\mathbf u}_1=0.
\]

\(\mathbf u_j=(u_j,v_j)\)は画像\(j\)の補正後の特徴点座標で、\(j=1,2\)は二視点の番号。\(u_j,v_j\)は左上原点、右・下を正とする画素単位の値である。\(\widetilde{\mathbf u}_j=(u_j,v_j,1)^T\)は同次座標、上付き\(T\)は転置を表す。\(H_{21},F_{21}\)は3×3行列で、全体に任意の非零倍率を掛けても同じ幾何を表す。\(\sim\)も非零倍率までの一致を意味し、長さの等号ではない。

Hは対応先の点を、Fは対応先が乗る直線を制約する。どちらも画像の幾何モデルであり、Hがよく当てはまるだけで奥行きが安定して求まったことにはならない。手元は両モデルの得点を比べて一方の復元へ進み、その失敗時に自動で他方を試す分岐にはなっていない。

## 理論2：姿勢とカメラ中心を区別する

カメラ校正を使ってH/Fから回転・並進の候補を作る。世界座標は最初のカメラ座標に合わせ、第1姿勢を単位変換とする。候補の第2姿勢が、世界から第2カメラへ変換する`Tcw`になる。

\[
\mathbf X_c=R_{cw}\mathbf X_w+\mathbf t_{cw},\qquad
\mathbf C_w=-R_{cw}^{T}\mathbf t_{cw}.
\]

\(\mathbf X_w\)は世界の3次元点、\(\mathbf X_c\)は同じ点のカメラ座標、\(\mathbf C_w\)は世界座標でのカメラ中心。\(R_{cw}\)は無次元の3×3回転行列、\(\mathbf t_{cw}\)は3成分の並進で、点・中心・並進は共通の任意長さ単位を使う。`Tcw`はこの回転と並進をまとめた剛体変換である。

カメラ座標の横は右、縦は下、奥行きは前向きである。カメラ中心自身のカメラ座標は0なので、上式に\(\mathbf X_c=0\)を入れてカメラ中心の式を得る。**`Tcw`の並進成分は、世界座標でのカメラ位置そのものではない。**

## 理論3：二つの視線から奥行きを求める

ピンホール投影を、本章では次のように表す。入力は歪み補正後の画像座標と対応させる。

\[
\pi(\mathbf X_c)=
\begin{pmatrix}f_xX_c/Z_c+c_x\\f_yY_c/Z_c+c_y\end{pmatrix}.
\]

\(\mathbf X_c=(X_c,Y_c,Z_c)^T\)の各成分は同じ任意長さ単位、\(Z_c\)は奥行きで、式の計算には\(Z_c\ne0\)を要する。可視点として採用する説明では前方の\(Z_c>0\)を想定する。\(f_x,f_y\)は画素単位の焦点距離、\(c_x,c_y\)は画素単位の主点座標。\(\pi\)は3成分から2成分の画素座標へ写す関数である。

三角測量は、両画像で観測した点に投影される3次元点を求める処理である。候補姿勢が違えば視線の交わり方も違うため、姿勢候補ごとに求め直し、再投影した位置や奥行き、視差を確認する。手元は同次座標の線形方程式を特異値分解で解く。ここでは行列解法の導出より、**両視線に整合する点を選ぶ**という役割を押さえる。

視差とは、異なるカメラ位置から同じ点へ向かう視線の角度差である。位置が変わらない純回転では、同じ視線上のどの奥行きも画像を説明でき、奥行きを一意に決められない。視差が小さくても推定は不安定になる。特徴数が多いことだけでは、この幾何的な不足を解決できない。[原論文PDF7頁、誌面6頁、§IV・図3][orb-slam]

## 理論4：初期BAで姿勢と点を調整する

採用点を地図へ登録した後、BA（Bundle Adjustment：複数画像での再投影誤差を小さくするよう姿勢と地図点を同時に調整する処理）を行う。単に点を増やす処理ではなく、観測された画素位置とのずれを減らす。

\[
\min_{\{R_j,\mathbf t_j,\mathbf X_i\}}
\sum_{(j,i)\in\mathcal O}\rho\!\left(\mathbf e_{ji}^{T}\Omega_{ji}\mathbf e_{ji}\right),\qquad
\mathbf e_{ji}=\mathbf u_{ji}-\pi(R_j\mathbf X_i+\mathbf t_j).
\]

\(j\)は2枚のKeyFrameの番号、\(i\)は採用した地図点の番号、\(\mathcal O\)は観測の組の集合で、番号に物理単位はない。\(\mathbf X_i\)は世界の3次元点、\(R_j,\mathbf t_j\)は世界からカメラ\(j\)への姿勢で、前節と同じ型・単位を持つ。\(\mathbf u_{ji}\)は補正済みの2次元観測、\(\mathbf e_{ji}\)は2成分の画素誤差である。

\(\Omega_{ji}\)は2×2の重み行列で、単位は画素の二乗の逆数。手元では特徴を抽出した段の逆分散を用いる。\(\rho\)はHuber損失で、大きな誤差の影響を単純な二乗より抑える。括弧内と損失は無次元になる。最初のKeyFrame姿勢を固定し、その制約下で他の姿勢と点を調整する。これは手元実装を説明する整理式で、原論文の式番号は付けない。

## 理論5：中央値を1とする任意尺度へそろえる

純単眼では、地図点と並進を同じ倍率で大きくしても、投影の比\(X_c/Z_c,Y_c/Z_c\)は変わらない。BAを終えても、画像だけからメートル単位の大きさは決まらない。

手元ではBA後、初期KeyFrameから見た点の奥行きの中央値\(d\)を求め、次のように数値を正規化する。

\[
\mathbf t_2\leftarrow\mathbf t_2/d,\qquad
\mathbf X_i\leftarrow\mathbf X_i/d\quad(d>0).
\]

\(d\)は初期カメラ座標の前向き深度で、ユークリッド距離ではない。正規化前は点と同じ任意長さ単位、正規化後は中央値を1とした地図座標の数値に表し直す。\(\leftarrow\)は値の更新を表す。並進と点を共に割るため投影は変わらず、実寸を測ったことにはならない。コードの中央値は整列した深度の下側の中央値で、偶数個の中央2値の平均ではない。

## 小さな例と限界

回転が単位行列で`Tcw`の並進が\((-1,0,0)^T\)なら、カメラ中心は世界座標で\((1,0,0)^T\)である。初期深度中央値が5なら、正規化後の並進は\((-0.2,0,0)^T\)、中心は\((0.2,0,0)^T\)、点の深度中央値は1になる。すべて任意尺度で、0.2メートルを測ったという意味ではない。

静止した場面、対応する同じ点、画像に合う校正、奥行きを分離できる視差が必要になる。動く物体、誤対応、純回転、小視差は結果を不安定にし得る。上の正規化式は\(d>0\)を前提にした説明で、コードがあらゆる数値異常を検出する保証ではない。今回は動画での初期化成否もH経路の発現も実測していない。

## 出典と理解確認

[ORB-SLAM原論文][orb-slam]のPDF6–7頁（誌面5–6頁）、§IV、式(1)–(4)、図3を本文・画像で確認した。[公式固定コミットのTwoViewReconstruction](https://raw.githubusercontent.com/UZ-SLAMLab/ORB_SLAM3/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4/src/TwoViewReconstruction.cc)も照合した。SLAMはSimultaneous Localization and Mapping、自己位置推定と地図作成を同時に行う方法である。詳細は [A06調査メモ](../research/A06_evidence.md)。

1. 二視点から、点の奥行きと何を一緒に求めるか。
2. `Tcw`の並進とカメラ中心は同じ値か。
3. 深度中央値を1にしたら、地図の単位はメートルになるか。
4. 特徴が多くても純回転では奥行きが決まらないのはなぜか。

答えの要点：相対姿勢／中心は\(-R^Tt\)／任意尺度のまま／カメラ位置が変わらず奥行きを区別する視差を得られない。
