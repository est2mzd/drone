# A07 初期化の成立判定

## 図の位置、背景と目的

図Aの **<成立した?>** に対応する。A06の初期地図作成から入り、**はい→A13「姿勢を得る・必要ならキーフレームを選ぶ」、いいえ→合流点Aから次画像へ**進む。

二視点の対応や姿勢候補が得られても、追跡の出発点として十分とは限らない。候補を保存する段階、幾何を復元する段階、作った地図を確認する段階を通った結果として成立を扱う。

本章の目的は、**何を満たすと先へ進み、不成立時には何を保持して次の画像を待つのか**を理解することである。純単眼の現行経路に限定する。

## 入出力と最後の判断

入力はA06で処理した現在Frame、初期候補の準備フラグ`mbReadyToInitializate`、対応・復元・初期地図の結果である。Frameは一枚の画像の特徴・時刻等を持つ入れ物、準備フラグは真/偽の値である。出力は初期化成立として処理を続けるか、現在画像の初期化処理を終えて次画像へ戻るかという分岐である。

`Tracking::Track`は初期化関数から戻った後、`mState != OK`なら現在Frameを保存して`return`する。最後の成立判断を整理すると次の式になる。

\[
A(s)=(s=\mathrm{OK}).
\]

\(s\)はその時点の`mState`で、型は`eTrackingState`という状態の列挙型、物理単位や空間の次元は持たない。\(A\)は状態から真/偽を返す述語で、\(A(s)\)が真なら図の「はい」、偽なら「いいえ」に対応する。等号は状態の一致判定で、座標変換の式ではない。

前提は、現行単眼の初期化呼出しが通常どおり戻ったことである。`OK`は候補を保存しただけでは設定されず、初期地図作成の末尾まで到達したときに設定される。

## 多段判定：値の意味と比較演算

次の表では、\(N\)を現在画像の特徴点数、\(M\)を初期画像との対応組数、\(P\)を後述する対象地図点数とする。すべて0以上の整数の個数で、同じ種類の点数ではない。\(d\)は初期地図の深度中央値で、任意の地図長さ単位を持つ実数値である。

| 段階・条件 | 条件に該当したときの動作 | 次画像への持ち越し |
| --- | --- | --- |
| 候補未準備で\(N>100\) | 現在Frameを初期候補へ保存し、準備フラグを真にして戻る | 候補を保持。まだ成立ではない |
| 候補未準備で\(N\le100\) | 初期候補として保存しない | 未準備のまま次画像を待つ |
| 候補準備済みで\(N\le100\) | 準備フラグを偽にして戻る | 次は候補の取得段階へ戻る |
| 対応探索後に\(M<100\) | 準備フラグを偽にして戻る | 次は候補の取得段階へ戻る |
| 二視点復元の戻り値が偽 | 地図作成を呼ばずに戻る。この箇所では候補・準備フラグ・状態を変更しない | 同じ初期候補と後続画像で再試行できる |
| 二視点復元の戻り値が真 | 三角測量の非採用対応を除き、初期地図作成へ進む | 真だけで最終成立とはしない |
| 初期BA後に\(d<0\)または\(P<50\) | 現在地図のリセットを要求して戻る | リセット要求を後続処理へ渡す |
| 初期地図作成の末尾へ到達 | `mState=OK`にする | `Track`の未成立時returnを通らず続行 |

BAはBundle Adjustmentで、姿勢と地図点を再投影誤差に合わせて調整する処理である。\(P\)は`pKFcur->TrackedMapPoints(1)`の値で、現在側KeyFrameに結びついた、無効でないMapPointのうち登録観測数が1以上あるものを数える。KeyFrameは地図用に残す重要画像、MapPointは3次元地図点である。引数の1は最低登録観測数で、50はその条件を満たす地図点の数である。

準備フラグの解除は、候補用変数のメモリを消す操作と同義ではない。次にどの処理段階へ入るかを変える。また、復元失敗時に候補を保持するとは、対応探索の作業配列まで全く変化しないという意味ではない。

## 現行コードへの対応

確認日2026-10-07、ORB_SLAM3 HEAD `4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4`。パスは`third_party/ORB_SLAM3/src/`基準。Systemには既存変更があるため手元の行番号を示す。

| ファイル・関数・行 | 表との対応 |
| --- | --- |
| `Tracking.cc:2451-2478` `MonocularInitialization` | 候補未準備時の\(N>100\)と保存 |
| 同`:2481-2499` | 準備済みの\(N\le100\)、対応\(M<100\)による解除 |
| 同`:2504-2522` | 復元の真偽による分岐。真のとき非採用対応を除外して地図作成へ |
| `Tracking.cc:2580-2593,2656` `CreateInitialMapMonocular` | BA後の\(d<0\)または\(P<50\)、末尾の`OK`設定 |
| `KeyFrame.cc:340-364` `TrackedMapPoints` | \(P\)に数える点の条件 |
| `Tracking.cc:1912-1915` `Track` | 初期化呼出し後、状態が`OK`以外ならFrame保存とreturn |
| `System.cc:514-518,450-471` `ResetActiveMap` / `TrackMonocular` | リセット要求フラグの設定と、後続単眼入力での処理 |

`System::ResetActiveMap`は要求フラグを立てる関数である。後続の`TrackMonocular`が呼ばれると、画像をTrackingへ渡す前の確認でリセット処理を呼ぶ。この要求を、その場でプロセスが終了した、またはAtlasの全地図が即時削除されたと解釈しない。Atlasは複数の地図を管理する器である。

二視点復元が真の場合、非採用対応を除いて\(M\)が減るが、その直後に再び\(M<100\)を確認するコードはない。後の地図点条件\(P<50\)と混同しない。ホモグラフィHと基礎行列Fは二視点の対応を説明する行列で、その得点比も**幾何モデルの選択**であり、図A07の最終成立そのものではない。

## 境界の例と限界

特徴点が100個なら候補保存の`>100`を満たさず、101個ならその条件を満たす。一方、対応が100組なら`<100`には該当せず復元へ進める。数値100が共通でも、比較対象と演算は異なる。

BA後の対象地図点が49個ならリセット要求、50個ならその点数条件を通過する。ただし、いずれの一条件を通過しても全体の成立を単独では保証しない。深度条件は厳密に`d<0`であり、0をこの条件で排除するわけではない。`d>=0`なら数値的に安全という意味にはならず、非有限値等の完全検査も保証しない。

慣性付き単眼専用の時間差条件は、ここで扱う純単眼の表へ含めていない。復元内部の全閾値も本章では列挙しない。手元H経路の点群出力に関する静的懸念は [A06の制約](06_A06.md) を参照し、復元の戻り値だけから正常動作を断定しない。実動画での成立・不成立は未測定である。

## 出典と理解確認

[固定コミットの公式Tracking.cc](https://raw.githubusercontent.com/UZ-SLAMLab/ORB_SLAM3/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4/src/Tracking.cc)を照合し、[ORB-SLAM原論文](https://arxiv.org/pdf/1502.00956v2)のPDF6–7頁＝誌面5–6頁・§IV/図3を本文と画像で再読した。論文の初期化方針と手元の候補解除条件は同一視していない。詳細は [A07調査メモ](../research/A07_evidence.md)。

1. 初期候補の保存だけで`OK`になるか。
2. 対応不足の場合と、二視点復元が偽だった場合で、候補の扱いはどう違うか。
3. `ResetActiveMap`要求を出した時点で全Atlasの削除が完了したと言えるか。

答えの要点：ならない／対応不足は準備解除、復元が偽ならこの箇所では保持／言えず、後続入力前に要求を処理する。
