# O01 結果の表示と再投影

図の対応：DFD（Data Flow Diagram、データの流れを示す図）の「別の表示ツール」と、境界図の「viewer・RViz」。接続は **D14,D15,D01 → 表示**。保存した点・姿勢・動画を読む、現行の二つの表示プログラムを扱う。

## 保存結果を見える形に変える

D14の点座標とD15の姿勢は数値列であり、そのままでは画像との対応を理解しにくい。表示ツールは点を箱にまとめて三次元的に見せたり、保存姿勢と校正を使って動画へ戻したりする。ここでSLAM（Simultaneous Localization and Mapping、自己位置推定と地図作成）を再実行するわけではない。

入口は`scripts/orb_slam3/view.sh`と`show_rviz.sh`である。前者は`slam/viewer/view.py`へ動画・点ファイルと追加引数を渡す。後者はROS 2（Robot Operating System 2）の環境を読み、三次元表示ツールRVizと`slam/rviz/play_map.py`を起動する構成になっている。今回はこれらを起動していない。

| 表示経路 | 主な入力と出力 |
| --- | --- |
| viewer通常 / `--save` | 動画と点から、仮想視点の箱表示と動画を左右に並べる。通常は操作画面、`--save`は指定先の動画 |
| viewer `--overlay` | 動画・点・姿勢と校正から、原画像へ箱を重ねた動画 |
| viewer `--check` / `--dump` | 並列表示の画像や表示上の検査。SLAM精度の評価ではない |
| RViz | 点・姿勢から、箱、原点、カメラ軌跡、座標変換をROSのメッセージとして表示。動画・校正ファイルは使わない |

viewerの`--overlay`は、姿勢指定がなければ点ファイルのstemに`_poses.txt`を付けて探す。出力は入力動画と同じ場所の`動画stem_div_XXX.mp4`へ自動命名する。オプションに渡した文字列を出力パスとしては使っていない。

点は4列` t x y z `、姿勢は9列` t tx ty tz qx qy qz qw valid `である。姿勢の並進は世界→カメラ変換の一部で、カメラ中心そのものではない。validの意味はD15の保存条件であり、追跡精度の保証ではない。

viewerは`mini3_calib/out/mini3.yaml`から3×3の内部行列Kと歪み係数をグローバルに読み込むため、通常表示にもこのファイルが必要である。ただし実校正を画像への投影に使うのはoverlay経路である。

## 箱は点をまとめた表示要素

ボクセルは、ここでは格子セルに対応する立方体状の表示要素を指す。両プログラムは全保存点の座標範囲から直方体の対角長を計算し、それを`voxel-div`で割った値を箱の一辺とする。80なら対角長の1/80であり、80メートルや固定された物理寸法ではない。対角長が微小な枝では一辺を1にする。

同じセルに複数点が入ると最早時刻を採るが、箱の中心は異なる。viewerは格子セルの幾何学的中心、RVizはそのセル内で最早時刻を持つ実点の位置を使う。従って、READMEの説明だけから両者が常に同じ位置の箱を描くとは解釈しない。

これは点をまとめる表示であり、壁面の復元、占有確率、障害物の体積の推定ではない。D14の座標は保存時の値、時刻は残存する観測関係から求めた値であるため、箱が現れる順番もオンライン地図生成を完全に再現した記録ではない。

## 仮想視点と実画像への投影を分ける

左側の三次元表示では、ユーザーが動かす仮想orbit視点と、表示用の焦点距離520を使う。これは実カメラのKとは別である。overlayでは、箱の頂点を保存姿勢で実カメラ座標へ変換し、Kと歪みを使って元画像の画素へ戻す。

有限な座標と整合した校正を仮定すると、後者はD03の歪みモデルを使って次のように書ける。

\[
X_c=R_{cw}X_w+t_{cw}=(x_c,y_c,z_c)^{\mathsf T},\quad
(a,b)=(x_c/z_c,y_c/z_c),\quad
(u,v)=\bigl(f_xD_x(a,b)+c_x,\ f_yD_y(a,b)+c_y\bigr).
\]

| 記号 | 型・座標・単位・前提 |
| --- | --- |
| \(X_w,X_c\) | 箱頂点の世界座標とカメラ座標。長さ3の実数列ベクトル、同じ地図の任意長さ単位 |
| \(R_{cw},t_{cw}\) | 世界w→カメラcの3×3回転と三成分並進。回転は無次元、正規直交で行列式＋1。並進は点と同じ長さ単位 |
| \(x_c,y_c,z_c\) | カメラ座標の右・下・前方成分。投影では\(z_c>0\)を仮定 |
| \(a,b\) | 正規化画像座標、二つの無次元実数 |
| \(D_x,D_y\) | D03の5係数による二次元歪み関数の各成分。係数`k1,k2,p1,p2,k3`、入力・出力とも無次元 |
| \(f_x,f_y,c_x,c_y\) | Kに入る正の焦点距離二成分と主点二成分、単位pixel |
| \(u,v\) | 元画像上の右・下を正とする二成分画素座標、単位pixel |
| \(\mathsf T\) | 転置。上式では成分を列ベクトルにする記号 |

コードは頂点へ先にTcwを適用し、得たカメラ座標を`cv2.projectPoints`へ渡す。この呼出しの回転ベクトル`rvec`と並進`tvec`はゼロであり、Tcwを二重に掛けない。歪み係数DISTを渡すので、歪み補正後の理想画素へ投影する式だけではこの経路を表せない。

説明用に歪みをゼロ、カメラ座標を`(1,0,5)`、焦点距離を両軸500 pixel、主点を`(320,240)` pixelとすれば、投影は`(420,240)` pixelとなる。これは仮定例で、現行校正値や実測結果ではない。実描画には奥行きや面、画素位置などの選別もあり、式と時間条件を満たす全箱が必ず描かれるとは限らない。

## 画像時刻に姿勢と箱を対応させる

overlayは画像の通し番号kとFPS（Frames Per Second、秒当たりの画像枚数）fから、秒単位の時刻\(t_k=k/f\)を作る。kは0始まりの整数、fは有限の正数で等間隔の画像列を表すと仮定する。姿勢時刻と画像時刻をそれぞれ小数5桁へ丸め、辞書のキーとして照合する。近い前後の姿勢を補間する処理ではない。

重複キーは原則先の行を保持するが、無効な先行行から有効行へ置き換える場合がある。対応姿勢がない、または保存validが0なら箱は重ねない。箱側は、その最早時刻が画像時刻以下であるものだけを候補とする。

例えばf=30、k=3なら画像時刻は0.1秒で、キーは0.10000に相当する。このキーの有効姿勢があるとき、時刻0.08秒の箱は候補、0.15秒の箱はまだ候補外となる。キーがなければ、0.09秒と0.11秒の姿勢から0.1秒の姿勢を作ることはない。

viewerのFPS取得は`get(...) or 30.0`であり、D02のwrapperの「1未満なら30」と同一の条件ではない。動画・保存時刻・校正・画像寸法が対応し、点と姿勢が共通の世界座標に属する必要がある。表示側がそれらを自動的に保証するわけではない。

## RVizは開始カメラを表示の原点にする

RViz側はvalidが0.5以上の姿勢行を抽出し、その抽出結果の最初の行を開始基準とする。有効行がなければ停止する。D15のTcwから中心\(C_w=-R_{cw}^{\mathsf T}t_{cw}\)を求め、次の変換を使う。

\[
X_d=R_0(X_w-C_0),\qquad C_d=R_0(C_w-C_0),\qquad
R_{dc}=R_0R_{cw}^{\mathsf T}.
\]

添字dは表示座標、0は最初の有効カメラである。R0はその世界→カメラ回転、C0はその世界座標の中心。Xdは表示点、Cdは表示カメラ中心で、どれも三成分・同じ任意長さ単位である。Rdcは現在カメラ→表示座標の3×3無次元回転であり、表示用の四成分クォータニオンへ変換する。

この処理で開始カメラ中心は原点になる。表示枠の名前は`map`だが、東・北・上や重力方向にそろえる変換ではなく、メートル尺度も追加で決めない。箱は`Marker/CUBE_LIST`、軌跡は`Path`、現在カメラは`map`から`camera`の座標変換として発行する。

タイマーは既定で30 Hzだが、有効姿勢行を一回に一件進める。隣り合う行が0.1秒と0.3秒でも、その0.2秒の差を待つ方式ではない。欠落や時間差がある場合の実時間再生を保証せず、末尾では最後の行を再発行する。ROSメッセージの時刻も保存時刻ではなく発行時の時計であり、Path内の各姿勢にも同じ発行時刻を付ける。

## 可視化で分かる範囲とコード対応

箱と画像が大きくずれるか、軌跡の形がどう見えるかを調べる助けになるが、表示だけで地図精度や実尺度は確定しない。`--check`も右パネルと動画の一致、箱数、視点変更による表示差などを調べるもので、真値との地図誤差や再投影残差の評価ではない。A23/D14/D15の保存完了・共通時点の保証範囲も変わらない。

## 理解確認

1. viewerの仮想焦点距離520と、overlayのK/DISTは何が違うか。
2. 姿勢ファイルの並進を、そのままRVizのカメラ位置に使えるか。
3. 30 Hzで行を進めること、箱が見えること、`--check`成功は、何を保証しないか。

答えの要点：表示視点用と実画像投影用／中心は負の転置回転を掛けて求め、さらに開始座標へ変換する／保存時刻差どおりの再生、面や占有の推定、SLAMの真値精度を保証しない。
