# D14 時刻付き地図点ファイル

図の対応：DFD（Data Flow Diagram、データの流れを示す図）の「時刻付き地図点ファイル」と、境界図の「点・姿勢ファイル」の点部分。接続は **A23 → O01**。現行プロジェクトが独自に追加した`SaveTimedMapPoints`の出力を扱う。

## 保存時の地図点を時刻付きで渡す

このファイルは、地図点の世界座標に一つの画像時刻を付け、後続の表示・利用へ渡すためのテキストである。点がいつから観測されているかを調べる材料になるが、全入力画像の点検出履歴を保存する形式ではない。

入力は出力先のファイル名と、呼出し時にAtlasが保持するMap・MapPoint・観測KeyFrameである。MapPointは三次元地図点、KeyFrameは地図の代表観測となるキーフレーム（以下KF）を指す。wrapperは`Shutdown`、親ディレクトリ作成の後に、この関数を無条件に呼ぶ（A23）。

出力はヘッダなし・空白区切りの` t x y z `で、一行が一つの採用点に対応する。これは既存ローカル差分の機能であり、固定した上流ORB-SLAM3の標準出力仕様ではない。

## 先にMapを選び、その後に点を選別する

| 順序 | 現行の処理 | 意味・境界 |
| --- | --- | --- |
| 1 | AtlasのMap一覧を取得 | 現在Mapだけを指定する処理ではない |
| 2 | 各Mapの`GetAllMapPoints().size()`を比較 | 点参照集合の件数であり、null/bad除外後の有効点数やKF数ではない |
| 3 | `n > best`のとき候補を更新 | 同数では更新せず、先に選んだ候補を保持する |
| 4 | 選択Mapの点一覧を再取得 | 比較時の点集合をそのまま固定して使う構造ではない |
| 5 | null/bad点、後述の時刻条件を満たさない点を除外 | Map選択時の件数と実際の出力行数は異なり得る |

`best`は0で始まるため、全Mapが0点なら選択先はない。Map一覧が空の場合も同様である。正の同数候補については先の候補が残る。`GetAllMaps`の返却一覧はMap ID（Identifier、識別番号）順だが、これを保存中の全データを凍結する保証と解釈しない。

例えばMap 0が集合4点、Map 1が集合3点なら、まずMap 0を選ぶ。Map 0のうち1点がbadで、別の1点に採用できる観測KFがなく、残る2点がnull/badでなく時刻条件も満たせば、出力は2行になる。Map 1に出力可能な点がより多くても、除外後の行数を比べ直して選び替える処理はない。いずれも集合が変わらない場合の仮定例である。

## 点に付ける時刻を観測表から求める

点ごとに現在の観測表を読み、nullのKFとbadのKFを除外する。ここでの選別は、この二つの条件だけであり、観測の幾何精度を全て検査して「良い時刻」を選んでいるわけではない。

実際の計算順は、`earliest`を正の無限大で始め、残った各KFの`mTimeStamp`とのminを反復し、最後に`isfinite(earliest)`を検査する、というものである。各KFの時刻を有限値かどうかで事前に選別する実装ではない。

対象観測が非空で、その時刻が全て有限という前提なら、結果を次の最小値として整理できる。

\[
t_P=\min_{K\in O(P)}t_K,\qquad
\mathrm{row}(P)=(t_P,x_P,y_P,z_P).
\]

| 記号 | 型・単位・意味 |
| --- | --- |
| \(P\) | 保存対象の一つの地図点を指す記号。位置ベクトルそのものではない |
| \(O(P)\) | 読み出した観測表にある、nullでもbadでもないKFへの参照の有限集合 |
| \(K,t_K\) | 一つの観測KFと、その`mTimeStamp`。時刻はdouble、単位は秒 |
| \(t_P\) | 前提下で得る最小の観測KF時刻。出力行に付けるdoubleの秒値 |
| \(x_P,y_P,z_P\) | 読み出した`GetWorldPos()`のfloat三成分。選択Mapの世界座標、単位は地図の長さ単位 |
| \(\mathrm{row}(P)\) | 時刻と位置からなる四要素の組を表す説明用記法。単一の空間座標ベクトルではない |
| \(\min,\in\) | 集合に属する各KFの時刻から最小値を求める演算と、集合への所属 |

観測が空なら`earliest`は無限大のままで、最後の有限性検査により点を出力しない。非有限の観測時刻が混ざる場合は上の式の前提外であり、「有限時刻だけを集めてmin」と読み替えず、反復後に判定する実装の順序で考える。

KFの時刻は元Frameから引き継いだ画像時刻で、このwrapperではD02の入力順番号と採用レートから生成される。保存時刻の最小値は、保存時に残る観測表の性質である。オンラインでの最初の検出時刻、点の生成処理時刻、実際の露光時計を永続記録する機構とは区別する。

古いKFがbadになったり、観測が解除されたり、点の置換によって観測関係が変わったりすれば、保存時に参照する集合も変わり得る。点座標も保存時に読む現在値なので、この時刻と座標の組を「その時刻当時に確定していた点位置」の記録とは解釈しない。

## 列・単位・並べ方

| 列 | 内容 | 表示と限界 |
| --- | --- | --- |
| `t` | 上記の最小KF時刻 | 秒。現在の処理経過時間ではない |
| `x y z` | 選択Mapの世界位置 | 純単眼では任意尺度。メートルや地理座標への変換を行わない |

行の内部型は`tuple<double,float,float,float>`である。通常の有限値では、標準sortが`t → x → y → z`の順に比較する辞書順で並べる。時刻が同じ行も座標で順番が決まるので、点一覧の走査順を保持する仕様ではない。

出力には`fixed`と`setprecision(6)`を指定し、有限値を小数点以下6桁で表示する。これは書式であって、六桁の測定精度を保証するものではない。点のID・所属Map ID・観測KF ID・有効性フラグ・ヘッダは各行に付けない。

座標三成分には有限性検査がない。従って、本章の通常数値の書式例や並び順を、非有限座標が混ざる場合の動作保証に広げない。時刻の最終検査があることと、全出力数値の品質検査があることは別である。

## 一点の行を読む例

点Pの観測表に、bad KFの1秒と、badでないKFの4秒・7秒が残っていると仮定する。採用する時刻は4秒となる。保存時の位置が`(1,0,5)`なら、その点の行は次のようになる。

```text
4.000000 1.000000 0.000000 5.000000
```

この行は、現在の点位置に、残っている採用対象KFの最小時刻4秒を付けたものと読む。1秒の観測は除外されているため、最初の観測時刻と一致するとは限らない。座標5も5mと確定した値ではない。全て説明用の数値で、実ファイルを作成した結果ではない。

## 保存完了の意味を限定する

関数はvoidで、ファイルのopen/write成否を検査しない。選択Mapがない場合でもofstreamを構築してから0件ログでreturnする。最後の`timed points`ログの件数も、行データを準備した件数であり、正常なファイル書込みを証明する値ではない。

現行`Shutdown`の終了待ちブロックはコメントアウトされており、参照一覧の取得も地図実体の固定コピーではない（A23/D10）。この出力から全最適化の完了、全行の同一時点性、別の姿勢出力との同一Map選択を無条件に保証しない。実際の入出力失敗や不整合を今回再現したわけではない。

## 理解確認

1. Mapを選ぶ件数と、出力行数は必ず同じか。
2. 点の時刻は、どの観測から・どの順序で求めるか。
3. 同時刻の行順と、小数点以下6桁・件数ログから保証できることは何か。

答えの要点：選択後に除外がある／現観測表のnull/badでないKFをmin反復し最後に有限性判定／座標まで含む辞書順、桁数やログだけでは精度・書込成功を保証しない。
