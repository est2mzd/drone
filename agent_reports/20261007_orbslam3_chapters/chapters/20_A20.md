# A20 既存地図を残す新地図開始

## 図の位置、背景と目的

図Bの **[既存地図を残し新地図を開始]** に対応する。**A19の保持側→A20→D10の地図情報とA22の次画像への接続**という位置である。対象は純単眼の`MONOCULAR`・通常SLAMで、`Tracking::CreateMapInAtlas`から`Atlas::CreateNewMap`を呼ぶ経路である。

SLAMはSimultaneous Localization and Mapping、自己位置推定と地図作成を同時に行う処理を指す。既存地図上で位置を追えなくなっても、それまでの地図を保持し、別の地図を使う準備ができる。Atlasは複数のMapを管理する器、MapはKeyFrameとMapPointなどを持つ一つの地図である。

KeyFrameは地図用に残す重要画像、MapPointは推定した三次元の地図点である。本章の目的は、旧地図を保持する操作と、追跡を始め直すための準備を理解することである。

入力は旧current（現在地図）、Atlas内の地図集合、現在画像を含むTrackingの情報である。出力は、旧地図を含む集合、新しいcurrent、再準備されたTracking状態である。この段階の新Mapはまだ地図の器で、初期姿勢や点群の構築完了を意味しない。

## Atlasで何が変わるか

`Atlas::CreateNewMap`はAtlasの排他ロックを取り、旧currentがあれば`SetStoredMap`を呼ぶ。次に新しいMapを作り、それをcurrentとして設定し、Atlasの地図集合へ追加する。旧Mapをこの関数で集合から削除する処理はない。

```text
呼出し前  Atlas { M_old [current] }
                       |
呼出し後  Atlas { M_old [stored], M_new [current] }
                                    新しい地図の器
```

`stored`はここでは「現在使用中ではない」側の印である。実体は`mIsInUse=false`への変更で、`SetStoredMap`がファイルへ地図を書き出すわけではない。新Map側では`SetCurrentMap`が同じフラグをtrueにする。

作成直前のAtlas内の有限集合を\(\mathcal A\)、旧地図を\(M_o\in\mathcal A\)、新地図を\(M_n\)とすると、この関数による変化は次のように整理できる。

\[
\mathcal A'=\mathcal A\cup\{M_n\},\qquad c'=M_n,\qquad M_o\in\mathcal A'.
\]

\(M_o,M_n\)はMapオブジェクトの識別用ラベル、\(c'\)は作成後のcurrent参照、プライム記号はこの作成処理の後を表す。\(\cup\)は集合への追加、\(\in\)は所属、波括弧は一要素の集合である。これらに物理単位や空間の次元・座標系はない。前提は旧Mapが登録済みの経路であり、並行処理も含めた将来のAtlas全体を固定する式ではない。

例えば旧MapだけのAtlasなら、この呼出しによって旧Mapと新Mapの二つを持つ。旧MapのKeyFrameやMapPointを新Mapへ複写するのではなく、新Map側の登録集合は作成時には空である。上図は地図の個数と参照の変化を示す例で、二つの地図を一つに融合する図ではない。

## 新しい地図と座標系

新Mapの容器を作っただけでは、旧Mapとの位置・向き・尺度の関係を推定していない。後で新地図が構築されても、単眼地図の数値座標は各地図の原点・向き・任意尺度に依存する。別地図で同じ数値の座標が現れても、それだけで同じ物理点を指すとは言えない。

同じ静止した物理点を、旧地図では\(\mathbf X_o\)、新地図では\(\mathbf X_n\)として表し、二地図が一つの相似関係で対応できる理想化を置くと、関係の一般形は次のようになる。

\[
\mathbf X_o=sR\mathbf X_n+\mathbf t.
\]

\(\mathbf X_o,\mathbf X_n\)は各地図座標系の3成分の位置ベクトルで、各単眼地図の任意長さ単位で表す。\(s>0\)は両地図の数値尺度を換算する無次元の倍率、\(R\)は新地図の軸を旧地図の軸へ回す3×3の正規直交行列で、行列式は+1、各成分は無次元である。\(\mathbf t\)は旧地図座標系で表す3成分の平行移動で、旧地図と同じ任意長さ単位を持つ。

これは未整合の意味を説明する一般式で、`CreateNewMap`が計算する式ではない。この関数は\(s,R,\mathbf t\)の推定や適用を行わない。両地図の誤差・ドリフトはこの式で評価しておらず、共通部分のない地図や誤った地図を必ず統合できるとも仮定しない。

## Tracking側で再準備する情報

`Tracking::CreateMapInAtlas`は、現在画像のIDを保存してAtlas側を呼び、その後、次のように追跡側の情報を再準備する。IDはIdentifier、識別番号である。Frameは一画像の特徴・時刻・姿勢等を持つ入れ物を指す。

| 対象 | 現行処理と意味 | `Tracking.cc`の行 |
| --- | --- | --- |
| 地図開始用の画像ID | `mnLastInitFrameId`へ現在Frame IDを保存し、`mnInitialFrameId`へそのID+1を設定する | 2664–2670 |
| 追跡状態 | `mState=NO_IMAGES_YET`。新Mapに対してまだ画像を処理していない状態を設定する | 2671 |
| 初期化準備 | `mbSetInit=false`、単眼の`mbReadyToInitializate=false`、`mvIniMatches.clear()` | 2668、2678–2681、2697 |
| 運動モデルと補助状態 | `mbVelocity=false`、`mbVO=false`として利用状態を再準備する | 2674、2677 |
| KeyFrame参照 | `mpLastKeyFrame`と`mpReferenceKF`をnullにする | 2689–2693 |
| 直前・現在Frame | `mLastFrame`と`mCurrentFrame`を`Frame()`に置換する | 2695–2696 |
| 地図作成フラグ | `mbCreatedMap=true`とする | 2699 |

`mvIniMatches`は単眼初期化用の対応記録で、この関数では消去する。VOはVisual Odometry、画像から移動を推定する処理を指す。`mbVO`はその経路に関係する補助フラグであり、新Mapを作ること自体が移動推定に成功したという意味ではない。

運動モデルはA09の相対姿勢変換である。ここでは`mbVelocity`をfalseにし、`mVelocity`の変換値そのものは再設定していない。`Frame()`も姿勢・速度などの有効フラグをfalseにする既定構築であり、全フィールドを数値0にするという説明は正しくない。

全Frame/KeyFrameの採番カウンタや全履歴をゼロへ戻す処理もこの関数にはない。特に`mnLastRelocFrameId`への代入は2675行のコメントで、実行されない。姿勢履歴リストを消去する処理もないため、「新地図開始ですべての過去情報を初期化する」とは解釈しない。

Atlas側は新MapにMap用カウンタからIDを付ける。新Mapの初期KeyFrame ID用の管理値は、Atlas集合が空でなく、その管理値が旧currentの最大KeyFrame IDより小さい場合に限って、旧最大値+1へ更新して渡す。すべての番号が毎回0に戻る処理でも、無条件に旧最大値+1になる処理でもない。

## 呼出しの範囲、コードと出典

この処理はTrackingからAtlasへの直接呼出しである。両関数には、LocalMapping（局所地図更新）やLoopClosing（再訪検出など）の停止・終了待ちを一律に行う呼出しはない。旧Mapが保持されることを、その後も非同期処理から一切変更されない保証として扱わない。

同様に、地図間の対応探索や座標の統合もこの作成処理では完了しない。A21のリセットとは処理が異なり、次画像からどの初期化経路へ進むかはA22へ接続する。本章はソースの静的読解であり、非同期の実行タイミングや再初期化の成否は未測定である。

## 理解確認

1. `SetStoredMap`は旧Mapをファイルへ保存する呼出しか。
2. `mbVelocity=false`や`Frame()`を「全数値をゼロにする」と説明してよいか。
3. 新Mapがcurrentになれば、旧Mapとの座標関係も求まり、統合が完了したと言えるか。

答えの要点：使用中フラグの変更／有効性や参照の再準備と数値の全初期化は異なる／作成だけでは座標関係を推定・適用していない。
