# P03 LoopClosingの補正と地図統合

図の対応：並行図・DFD（Data Flow Diagram、データの流れを示す図）の「LoopClosing」。接続は **D09,D07,D10 → D12**。P02から処理済みKeyFrameを受け、検索用データベースとAtlasの地図群を使い、補正・統合した地図を共有情報へ反映する。

対象は純`MONOCULAR`の通常SLAM（Simultaneous Localization and Mapping、自己位置推定と地図作成の同時実行）。KeyFrameは地図に残した代表画像と姿勢・観測、MapPointは三次元の目印である。LoopClosingは別スレッドで動き、その名前に反して別Mapの統合も担当する。

BAはBundle Adjustment（画像の再投影誤差を使う姿勢・点の調整）の略である。ORB（Oriented FAST and Rotated BRIEF、方向を付けた特徴点と二値記述子）の生成はA04で扱った。本章では地図に残った特徴対応を使う。

## なぜ過去の場所を探し直すのか

近隣画像を使う追跡・局所地図更新だけでは、小さな誤差が積み重なり、再訪した場所が以前とずれた位置に復元され得る。単眼では向き・位置だけでなく尺度もずれ得る。別々に初期化したMap同士には、初めから共通の座標系・尺度が設定されていない。

P03は離れた時点の観測を結び直して整合を取り直す。入力はP02からのKeyFrame、過去の検索表現、姿勢・点・観測関係。出力は採用された場合の姿勢・点・接続・所属Mapの更新であり、候補不成立なら補正を行わない。出力データの詳細はD12へ譲る。

```text
P02のKeyFrame → キュー → 場所の候補検索 → 幾何的な共通領域の確認
                                      ├─ 別Map: MergeLocal
                                      │          座標整合・融合・接合BA・所属移動
                                      └─ 同Map: CorrectLoop
                                                 補正・融合・姿勢グラフ・条件付き全体BA
```

`Run`はmergeの検出を先に扱い、その処理で同時に立ったloop検出も解除する。そのため、両方が検出されたら二つの処理を必ず連続実行する、という図の読み方はしない。

## 似た画像は候補であり、補正の根拠は幾何で確かめる

BoW（Bag of Words）は特徴記述子を視覚的な語の集計へ変えた画像検索表現である。検索用データベースの`DetectNBestCandidates(...,3)`は、同じMapの候補と別Mapの候補を分けて返す。同じ模様が別の場所にある場合もあるので、検索順位だけでは地図を結ばない。

現行の`NewDetectCommonRegions`は場所認識が無効なら戻り、有効な場合にキューからKeyFrameを取り出す。対象地図のKeyFrame数が12未満の場合などには共通領域の検出へ進まず、データベース登録を行って戻る。

| 段階 | 調べるものと意味 |
| --- | --- |
| BoW候補を集める | 候補KeyFrameと共視近傍から特徴対応を集める。共視とは同じ地図点を観測する関係 |
| 三次元対応を検証する | 両側の特徴に結び付くMapPointを使い、`Sim3Solver`で尺度付き変換の仮説を求める |
| 投影と変換を改善する | 仮説で点を画像へ投影して対応を増やし、`OptimizeSim3`で変換を調整し、再度投影探索する |
| 他の観測でも確かめる | 現在KeyFrameの共視KeyFrameへ変換を伝播して幾何確認し、一致数を検出判断へ使う |
| 継続候補を確かめる | 保存候補があると次のKeyFrameへ予測を伝播し、投影対応によって再検証する経路もある |

仮説検証にはRANSAC（Random Sample Consensus、少数の対応から仮説を作り、多数の対応による支持を調べる方法）を使う。姿勢の分かる二つの地図側の三次元対応が対象であり、A15の二次元・三次元対応から現在カメラ姿勢を求める処理とは役割が異なる。

新規候補の経路では、共視KeyFrameでの検証成功数を数え、保存した一致数が3以上なら検出成立を返す。足りない場合に後続KeyFrameで検証を続ける経路もある。旧論文の「BoWの整合した候補が連続3回現れる」を、現行の必須待ち時間として転記できない。

## Sim3は位置・向きに尺度を加える

Sim(3)（三次元の相似変換群）の要素を`Sim3`と呼ぶ。座標系Bの三次元点を座標系Aへ変える最小モデルは、次のように書ける。これは現行の変換作用を整理した式で、論文の式番号を付けた転載ではない。

\[
X_A=S_{AB}(X_B)=s_{AB}R_{AB}X_B+t_{AB},\qquad
S_{AB}^{-1}(X_A)=s_{AB}^{-1}R_{AB}^{\mathsf T}(X_A-t_{AB}).
\]

| 記号 | 型・座標系・単位・前提 |
| --- | --- |
| A,B | 変換先・変換元の三次元座標系のラベル。地図座標やKeyFrameのカメラ座標を区別して指定する |
| \(X_A,X_B\) | 同じ物理点を各座標系で表した実数3成分の列ベクトル。各地図の任意の長さ単位 |
| \(S_{AB}\) | B→Aの相似変換。逆変換の上付き\(-1\)はA→Bを表す |
| \(R_{AB}\) | 3×3の正規直交行列で行列式+1の回転。無次元。上付き\(\mathsf T\)は転置 |
| \(s_{AB}\) | 正の実数の尺度比。座標の数値間の無次元倍率であり、メートルへの校正値とは限らない |
| \(t_{AB}\) | A側で表した実数3成分の並進。A側の長さ単位 |

回転3・並進3・尺度1の計7自由度を扱う。共通の静的領域が一つの相似関係で近似でき、十分な正しい対応が得られることを前提とする。局所的な変形や累積誤差まで、一つの変換で必ず解消できるという式ではない。

例えば回転が単位行列、尺度が2、並進がA側で`(1,0,0)`、B側の点が`(1,0,2)`なら、A側の点は`(3,0,4)`になる。B側の形を2倍して向き・原点を合わせた数値例であり、点までの実距離が4メートルと分かったわけではない。

現行の`Scw=Scm*Smw`は、候補Mapの世界座標w→候補カメラm→現在カメラcを右から左へ合成する。純単眼ではSystem生成時に尺度固定をfalseにしている。SE(3)（尺度を持たない三次元剛体変換）としてKeyFrame姿勢へ保存する際は、補正Sim3の並進をその尺度で割る処理がある。これは透視投影の方向を保つ表現であり、Sim3とSE3を同じ三次元変換として扱う操作ではない。

## 同一Map：CorrectLoopが補正を地図へ広げる

`CorrectLoop`はLocalMappingに停止を要求し、キュー処理を行う`EmptyQueue`を呼び、`isStopped()`を待つ。実行中の全体BAがあれば中断を要求する。そのうえで現在KeyFrameと共視近傍へ補正Sim3を伝播する。

観測点は、補正前の姿勢でカメラ座標へ写し、補正後の姿勢の逆で地図側へ戻して位置を更新する。姿勢だけを変えて点を置き去りにせず、同じ観測との関係を保ちながら周辺を補正するためである。

次に重複したMapPointを`Replace`や投影探索によって融合し、観測を結び直す。共視接続も更新するので、単に二つの点配列を連結する処理とは異なる。

純単眼では`OptimizeEssentialGraph`を呼ぶ。Essential GraphはKeyFrameを頂点とし、木・ループ・強い共視関係などから選んだ相対変換を辺に持つ姿勢グラフである。相対関係の矛盾を小さくするようSim3姿勢を調整し、補正を地図の他の部分へ伝える。現行は初期KeyFrameを固定する。

姿勢グラフは相対変換の整合を主に扱い、BAは画像の再投影誤差を使って姿勢と点を調整する。姿勢グラフでも結果に応じて点座標は更新されるが、全点を同時に自由変数として解くBAと同じ最適化ではない。

ループ辺を登録した後、条件が成立すればGBA（Global Bundle Adjustment、対象Mapの全体BA）を別スレッドで起動する。条件は`!isImuInitialized() || (KeyFramesInMap()<200 && CountMaps()==1)`。純単眼では前半が成立するため「200枚未満の地図だけ」とは説明できない。LocalMappingの再開はGBA完了を待つこととは別である。

## 別Map：MergeLocalが座標と観測の所属を合わせる

別地図の統合では、現在側と対応先側の共視近傍から接合用の窓を作る。`MergeLocal`はLocalMappingの停止を待ち、現在側の窓の姿勢・点を対応先Mapの座標へ合わせ、所属を移す。Atlasのcurrentを対応先へ変更し、元Mapをbadとして扱う。

木の親子関係を組み直し、重複点を投影探索で融合して観測接続を作る。その後、接合部分のwelding BAを呼ぶ。weldingはここでは、二つの地図の接合部を観測に基づいて調整する意味である。

| 現行`LocalBundleAdjustment`の引数 | この版での扱い |
| --- | --- |
| 第2引数：現在側の窓のKeyFrame | 有効な姿勢を可動変数にする |
| 第3引数：対応先側の窓のKeyFrame | 有効な姿勢を固定する |
| 上記から集めたMapPoint | 三次元位置を可動変数にし、採用した画像観測の再投影誤差で調整する |

再投影残差・重み・単位は[P02](25_P02.md)と同じ考え方を使い、可動・固定集合をこの表へ置き換える。ただし呼ばれるのは`Optimizer.cc:3498`の別版で、Huberによる外れ値の影響抑制付き5反復を要求し、継続時に外れ観測を除外・Huberを解除して10反復を要求する。P02の一段の局所BAとは区別する。

ORB-SLAM3論文の図3(a)・本文は窓の両側を可動、窓の外の観測KeyFrameを固定と説明するが、現行呼出しは上表の構成である。固定姿勢があっても単眼の任意尺度が実メートルに変わるわけではない。

接合BA後にLocalMappingを一度再開し、元Mapに残りの要素があれば、純単眼枝でそれらの姿勢・点へ変換を伝播する。再びLocalMapping停止を待って所属を移すが、後半の`OptimizeEssentialGraph`は`MONOCULAR`以外の条件内にあり、本章の経路では呼ばない。論文の統合手順を全センサー共通の現行手順とはしない。

最後にmerge辺・変更情報を更新し、bad MapをAtlasの管理集合から除く。A20は独立した新Mapを開始する操作だったのに対し、ここでは既存の二つのMapの対応を使って座標と観測を統合する。どの領域も必ず一致する、誤対応が皆無になるという保証ではない。

## 停止要求・最適化結果・処理完了を区別する

| 処理 | 確認できる範囲 |
| --- | --- |
| 補正・統合時のLocalMapping停止 | 停止要求後に停止フラグを待つ。全スレッドやAtlas全体を一律に終了させる操作ではない |
| 実行中GBAの中断 | stopフラグと世代値を更新し、スレッドを`detach`する。`join`による終了待ちではない |
| merge後のGBA再起動 | 冒頭で実行中GBAを中断したことを示す`bRelaunchBA`も必要。全mergeで毎回起動するわけではない |
| GBAの結果反映 | stop等を検査し、LocalMapping停止とMapのmutex（相互排他ロック）取得を経て、木を通じた補正伝播・姿勢と点の書戻しへ進む |

GBA計算中に追加されたKeyFrameには、木の相対関係を使って補正を伝える経路がある。計算対象の取得・計算・共有地図への反映は別の段階であり、関数を呼んだことだけでは収束や全処理完了を示さない。

現行GBAでは世代比較用の`idx`を最適化呼出し後に取得している。比較があることだけから古い結果が必ず完全排除されるとは断定しない。また、接合BAのstopは呼出し側の局所変数であり、P02の`mbAbortBA`と同じ変数ではない。並行実行時の採否や競合は今回実行検証していない。

## 理解確認

1. BoWで似た画像が見つかっただけで、同じ場所と確定できるか。
2. 現行純単眼のmergeは、必ず後半の姿勢グラフ最適化と新しいGBAを実行するか。
3. `s=2`を推定できたら、統合後の座標は必ずメートル単位になるか。

答えの要点：幾何検証が必要／後半グラフは本経路で非実行、GBA再起動にも条件がある／地図間の尺度比であり、実距離の校正とは別。
