# D05 画像とフレーム時刻

図の対応：DFD（Data Flow Diagram、データの流れを示す図）の「画像・フレーム時刻」。接続は **A03 → A04,D06**。A03で読み出した画像と付与した時刻を、特徴抽出とFrame構築へ渡すデータの組を扱う。

## 一つの観測として受け渡す

画像は「何が見えたか」、時刻は「時間軸上のどこに置くか」を表す。一枚の画像と、それに付けた時刻を対応させることで、後続処理がその観測を時間付きで扱える。画素に時計の文字を描き込む処理ではない。

現行wrapperの`TrackMonocular(frame, timestamp)`は、この二つを同じ呼出しの別引数として渡す。入力の組を次のように表す。

\[
U_k=(I_k,t_k),\qquad t_k=\frac{k}{f}.
\]

| 記号 | 型・次元・単位・意味 |
| --- | --- |
| \(U_k\) | 画像と時刻からなる二要素の組。三次元位置や同じ型の数値ベクトルではない |
| \(I_k\) | k番目の読込成功画像。コードでは`cv::Mat`で、H×W画素・Cチャネルの配列 |
| H,W,C | 正の整数。Hは高さ、Wは幅の画素数、Cはチャネル数。要素型と実寸は本章で実測していない |
| \(k\) | 0始まりの入力順番号。コードでは`int frame_index`、単位は画像を数える番号 |
| \(f\) | wrapperが採用するレート。式では有限で正の実数、単位は画像数/秒 |
| \(t_k\) | 画像へ付ける相対時刻。コードでは`double timestamp`、単位は秒。先頭は0秒 |

式は一定レートで並ぶ画像列とみなすモデルで、空間座標を変換するものではない。採用レートの規則と、撮像時刻・動画内時刻・処理経過時計との違いはD02を参照する。この式を使うこと自体が、実際の露光時刻との一致を検証するわけではない。

## SystemからFrameへ渡る経路

```text
wrapper: read成功 → frame と timestamp
    ↓ TrackMonocular(const cv::Mat&, const double&, ...)
System: 画像をclone → 設定が要求するときresize
    ↓ imToFeed と同じtimestamp
Tracking: GrabImageMonocular → グレー化 → Frameを構築
    ↓
Frame: mTimeStampへ値を保存、mnIdは別カウンタから採番
```

Systemの引数がconst参照であることは、内部で複製しないことを意味しない。現行は`im.clone()`で内部用画像を作り、必要時にはリサイズした画像を`imToFeed`とする。元の同一バッファを永久に共有して保持する、という契約ではない。

現行の校正ファイルには新寸法の指定がないため、その設定に基づくリサイズは要求されない。寸法や色順の前提はD03を参照する。画像を前処理しても、Systemは同じtimestampを`GrabImageMonocular`へ渡す。

Trackingは画像をグレー化する経路を経て、画像とtimestampからFrameを構築する。コンストラクタは`mTimeStamp(timeStamp)`で時刻をdoubleの**値として保存**する。呼出し側の時刻変数への参照を、そのままFrameの時刻として持ち続ける説明にはしない。

## 入力順、時刻、Frame IDは別の値

| 値 | 生成元・役割 |
| --- | --- |
| 画像配列 | `read`で取得した見え方。複製・前処理の対象 |
| `frame_index` | wrapperが0から増やす入力順番号。時刻の計算へ使う |
| `mTimeStamp` | 呼出しで渡された画像時刻を保存したdoubleの秒値 |
| `mnId` | Frame ID（Identifier、識別番号）。`nNextId++`で採番する符号なし整数 |

`mnId`とstaticな`nNextId`の型は`long unsigned int`である。wrapperは自分の`frame_index`をFrame IDとして渡していない。単純な連続入力で数値が一致する場面があっても、別管理の番号であり、一般に同じ値であることを入力契約にしない。Frameのほかの保持情報はD06で扱う。

例えば採用レートが30なら、最初の三組は`(I_0,0秒)`、`(I_1,1/30秒)`、`(I_2,2/30秒)`となる。三番目の画像を処理するのに長くかかっても、このwrapperが生成する時刻は`2/30秒`のままである。Frameにはこの秒値が保存され、IDにはその時点の採番値が入る。

この例は計算上の対応を示すもので、動画の実時刻を測定した結果ではない。画像と時刻を一組で渡す設計と、時刻が撮像の真値であること、追跡が成立することは別に確認が必要である。

## 理解確認

1. Systemがconst参照で画像を受けることは、内部cloneがないという意味か。
2. Frameへ渡した時刻は、値と参照のどちらとして`mTimeStamp`へ保存されるか。
3. wrapperの画像番号、画像時刻、Frame IDを一つの番号として扱ってよいか。

答えの要点：内部にcloneがある／doubleの値／用途も生成経路も異なるため区別する。
