# A02 次画像の有無と動画ループ

## 図の位置

図Aの **<次の画像がある?>** に対応する。A01の入力準備、または各画像の処理後に戻る合流点Aから入り、**はい→A03「画像を読む・時刻を付ける」、いいえ→A23「終了要求・結果保存」** へ進む。

この図は仕事を分けて説明している。実装では、画像を取得する呼出しの戻り値をそのまま判断に使うため、A02の判断とA03の画像読込部分は一つの操作に重なる。

## 背景と目的

保存動画を処理するときは、一枚を処理した後で次の画像へ進む反復が必要になる。取得できない画像を追跡へ渡さず、画像列を進められなくなった時点で終了処理へ移るために、この判断がある。

本章の目的は、**何がループを続ける条件なのか、falseから何が分かり何が分からないのか**を説明できることである。追跡結果の良否を判断する章ではなく、動画入力を進める判断を扱う。

## 入出力と処理の意味

| 項目 | 内容 |
| --- | --- |
| 入力 | 開いてある動画入力`capture`と、画像を受け取る変数`frame` |
| 実行する操作 | `capture.read(frame)`で次画像を取得・デコードする |
| 成功時 | `frame`へ画像が入り、戻り値が`true`（真）となってループ本体へ進む |
| 取得不能時 | 戻り値が`false`（偽）となり、ループを抜ける |

`read`はOpenCV（Open Source Computer Vision Library：画像・動画処理のライブラリ）の関数である。公式文書は、次フレームを取得してデコードし、取得できない場合はfalseを返して出力画像を空にすると説明する。[OpenCV公式 `VideoCapture::read`](https://docs.opencv.org/4.13.0/d8/dfe/classcv_1_1VideoCapture.html)

ここでデコードとは、動画ファイル中の圧縮された情報から画像を取り出すこと。`read`は「次があるかだけを調べる」操作ではなく、動画の読込状態と出力画像を変える操作である。

## 必要な式：取得結果で次の活動を選ぶ

教材用に、各呼出しの戻り値を次のように書く。論文の推定式ではない。

\[
b_j=\operatorname{read}(\mathrm{frame}),\qquad b_j\in\{\mathrm{true},\mathrm{false}\}.
\]

| 記号 | 型・単位・前提 |
| --- | --- |
| \(j\) | 0始まりの読込試行番号。0以上の整数、単位なし。失敗した試行も数える |
| \(b_j\) | 第\(j\)回の戻り値。ブール型で、数値の長さや座標ではない |
| \(\operatorname{read}\) | 開いている動画入力に対する読込操作。状態と出力画像を変えるため、単なる存在判定ではない |
| \(\mathrm{frame}\) | 出力画像を保持する`cv::Mat`型の変数。画素配列を受け取る |

前提は、呼出しが通常どおり戻り値を返すことである。この式では画素位置の計算をせず、世界・カメラ・機体の幾何座標系も使わない。分岐は、\(b_j\)が真ならループ本体、偽ならループ外の終了処理である。

`false`は「次画像を取得できなかった」という結果を表す。EOF（End of File：ファイル終端）に達した場合も含むが、その他の取得失敗もあり得る。したがって、この一つのブール値だけで正常終端を確定してはいけない。

## 現行コードとの対応

確認日2026-10-07、主プロジェクトHEAD `d1265bc35439dd6ca57687ac93c8b3a7310fc681`。対象`slam/src/offline_mono.cpp`はこのHEADから差分なし。以下はすべて同ファイルの`main`である。

```cpp
while (capture.read(frame)) {  // 45行：取得成功なら本体へ
    // 取得した画像の処理
    frame_index += 1;         // 54行：本体の末尾
}
slam.Shutdown();              // 57行：ループ退出後
```

| 行 | 図・理論との対応 |
| --- | --- |
| 27–30 | 動画を開けたかを先に確認する。ここで失敗した場合は今回のループへ到達しない |
| 41–45 | 出力画像用変数と0開始のカウンタを用意し、`read`の真偽で反復する |
| 47、54–55 | 成功画像を追跡本体へ渡し、本体末尾でカウンタを増やして次の`read`へ戻る |
| 57–63 | falseによる通常の退出後、終了要求と保存の呼出しへ進む。詳細はA23 |
| 67 | 末尾へ到達した場合、処理枚数が正なら終了値0、0枚なら1を返す |

`main`にはfalseの理由を分類する分岐、理由別ログ、再試行がない。継続条件は画像取得の成否であり、追跡状態の確認はこの条件を書き換えない。終了値0から分かるのも、末尾へ到達し処理枚数が正だったことまでで、動画全体の正常読了までは証明しない。

## 具体例：3枚取得した後にfalseが返る

`read`の結果が順に`true, true, true, false`だったと仮定する。各ループ本体が最後まで完了すれば、読込試行は4回、画像を処理する本体は3回、`frame_index`は0→1→2→3となる。4回目は偽なので、本体へ入らずカウンタも増えない。

最後のfalseが正常な動画終端だったのか、途中の取得失敗だったのかは、この列だけでは決められない。この例はコードをたどった説明であり、実動画を使った試験結果ではない。

## 論文との関係、成立条件と限界

ORB（Oriented FAST and Rotated BRIEF：画像の目印を検出し見た目を記述する方式）を用いるSLAM（Simultaneous Localization and Mapping：自己位置推定と地図作成を同時に行う方法）が本体の役割である。論文図1はFrameという画像単位の入力からTracking（追跡担当）へ進む構成を示すが、今回の自前ラッパーの`while`やEOF処理は描いていない。[論文PDF、5頁・図1/III節](https://arxiv.org/pdf/2007.11898v2)

本章は保存動画に対する、`read`が戻り値を返す場合の静的な確認である。破損動画、動画読込の内部実装ごとの差、例外やプロセス異常終了は実測していない。公式OpenCV文書の版は4.13.0であり、手元バイナリのリンク版と一致するかも未確認である。

## 出典と理解確認

行番号・公式文書の実読箇所・キャッシュPDFの再読記録は [A02調査メモ](../research/A02_evidence.md) に記録した。

1. 図の「次があるか」と画像の読込は、実装では別の関数呼出しか。
2. falseから「動画を最後まで正常に読めた」と結論できるか。
3. `true, true, true, false`なら、読込試行とループ本体はそれぞれ何回か。

答えの要点：同じ`read`呼出し／正常終端以外の取得失敗も含むため結論できない／4回と3回。
