# D03 カメラ校正と座標の前提

図の対応：DFD（Data Flow Diagram、データの流れを示す図）の校正「画像と視線の対応」。接続は **校正結果 → A01,A04,A06,A09,A10**。校正は、画像のどの画素がカメラから見てどの方向に対応するかを定める。

対象は現行の純単眼・`PinHole`設定である。SLAM（Simultaneous Localization and Mapping、自己位置推定と地図作成の同時実行）では、画素と三次元点を何度も対応付ける。その前提になる内部パラメータ・歪み・画像条件を、地図の姿勢や尺度から分けて理解する。

## 現在どの校正値を使うか

`run.sh`が渡す設定は`mini3_calib/out/mini3.yaml`で、`File.version: "1.0"`の読込経路を使う。入力はこの設定と画像、利用結果は投影・特徴点の歪み補正・必要な場面での視線計算である。

| 現行の保存値 | 意味 |
| --- | --- |
| `fx=895.475604, fy=894.667309` | 横・縦方向の焦点距離を画素単位で表した値 |
| `cx=641.024514, cy=359.282471` | 主点の画素座標。光軸が理想画像面と交わる点で、画像中心と厳密に同じとは限らない |
| `k1=0.11208777, k2=-0.28496497, k3=0.28816471` | 半径方向の歪み係数 |
| `p1=0.00023454, p2=0.00024400` | 接線方向の歪み係数 |
| `width=1280, height=720, Camera.RGB=0` | 校正が対応する画像寸法と入力の色順の設定 |

README等に残る焦点距離約733画素の初期値を、現在の読込値とは扱わない。現行コードが選ぶ上記ファイルを基準とするが、今回その値の測定や動画との適合検査を行ったわけではない。

## 校正ファイルができるまで

`calibrate.py`は、非対称に並んだ円の既知の中心座標と、画像で検出した円中心の画素座標を集め、OpenCV（Open Source Computer Vision Library、画像・動画処理ライブラリ）の`calibrateCamera`を呼ぶ。複数の見え方を同じカメラモデルで説明できるよう、内部パラメータ・歪みと各撮影時のパターン姿勢を推定する。

`pattern.object_points`の平面座標の単位はmmである。校正画像群の寸法が混在すると拒否し、円が揃った画像が既定の6枚未満なら終了する。ただし6枚あれば必ず十分な精度になる、という幾何的な保証ではない。

返却された内部パラメータと歪み、画像寸法などをYAMLへ保存する。一方、各画像の回転・並進`_rvecs/_tvecs`は保存しない。パターンにmmを与えたことだけで、後から別の動画で作る単眼地図がmm尺度に決まる経路ではない。

## 歪みのないピンホール投影

カメラ中心を原点、右をX、下をY、前方をZとする。画像の画素座標はuが右、vが下に増える。本章の式はカメラ座標の点から始まり、世界座標からカメラ座標への姿勢変換はA06/A09を参照する。

\[
P_c=(X,Y,Z)^{\mathsf T},\qquad x=X/Z,\quad y=Y/Z,\qquad
K=\begin{bmatrix}f_x&0&c_x\\0&f_y&c_y\\0&0&1\end{bmatrix},
\]
\[
u_u=f_xx+c_x,\qquad v_u=f_yy+c_y.
\]

| 記号 | 型・単位・前提 |
| --- | --- |
| \(P_c,X,Y,Z\) | \(P_c\)は実数3成分の列ベクトル、X/Y/Zはその成分。全て同じ長さ単位。本章では前方点\(Z>0\)を仮定し、単眼地図の実単位は未確定 |
| \(x,y\) | 実数の正規化画像座標。長さをZで割った無次元量 |
| \(K\) | 3×3の内部パラメータ行列。ここでは斜交成分0のピンホールモデル |
| \(f_x,f_y,c_x,c_y\) | 実数、単位は画素（px）。逆行列には\(f_x,f_y\ne0\)が必要で、通常は正。K最下行の定数は無次元 |
| \(u_u,v_u\) | 歪みのない画像面の実数画素座標。添字uはundistortedを区別するラベル |
| \(\mathsf T\) | 転置を示す上付き記号。横に並べた成分を列ベクトルへする |

`Pinhole::project`はこの投影を実装する。上の正深度は説明の前提であり、この関数単体が`Z>0`を検査するという意味ではない。焦点距離が画素単位なので、センサー上のmm単位の距離をそのまま代入するものでもない。

## 歪みありの画素と、補正後の画素

現行の5係数を使うOpenCVモデルでは、正規化座標に歪みを加えてから画素へ移す。次はその整理式で、ORB-SLAM3論文の式番号を付けた転載ではない。

\[
r^2=x^2+y^2,\qquad a=1+k_1r^2+k_2r^4+k_3r^6,
\]
\[
x_d=xa+2p_1xy+p_2(r^2+2x^2),\qquad
y_d=ya+p_1(r^2+2y^2)+2p_2xy,
\]
\[
u_d=f_xx_d+c_x,\qquad v_d=f_yy_d+c_y.
\]

\(r\)は正規化画像面の原点からの非負の距離、\(a\)は半径方向の倍率で、共に無次元の実数。\(k_1,k_2,k_3,p_1,p_2\)も無次元の実数係数である。\(x_d,y_d\)は歪みを加えた無次元座標、\(u_d,v_d\)はその画素座標。添字dはdistortedを区別するラベルである。

ピンホール本体は4個の内部パラメータを保持し、歪みは別のベクトル`[k1,k2,p1,p2,k3]`で扱う。歪みありの画素へ、補正済みを前提とする逆K変換をそのまま適用すると、意図した視線とはずれる。

```text
入力画像 → グレー化 → 特徴抽出 → mvKeys（歪みありの特徴点座標）
                              ↓ UndistortKeyPoints
                          mvKeysUn（補正後の画素座標）
                              ↓ 視線が必要な算法で逆投影
                          正規化した視線方向
```

`Frame`は画像全体を先に歪み補正するのではなく、特徴抽出後に特徴点座標を補正する。`undistortPoints`は逆歪みを反復的に近似し、現行呼出しは出力投影行列として`P=mK`を渡す。そのため`mvKeysUn`は**補正後の画素座標**であり、この時点の出力が正規化座標になっているわけではない。

現行`Frame::UndistortKeyPoints`はk1だけが0ならコピーして戻る。全歪み係数が0かを検査する条件ではない。現在のk1は非零で、この早期分岐には当たらない。

## 画素から得られるのは深さではなく視線

補正後の画素から視線を必要とするときには、次の変換を使える。`Pinhole::unproject`もこの形であり、全特徴に対して補正直後に一律に呼ぶ、という処理順を主張する式ではない。

\[
q=K^{-1}(u_u,v_u,1)^{\mathsf T}
=\big((u_u-c_x)/f_x,\ (v_u-c_y)/f_y,\ 1\big)^{\mathsf T},
\qquad P_c=Zq.
\]

\(K^{-1}\)はKの逆行列。\(q\)はカメラ座標軸に沿う実数3成分・無次元の視線表現で、z成分を1に揃えている。一般に長さが1の単位ベクトルではない。未知の正の深さZが残るため、qだけでは三次元点の位置が決まらない。

例えば補正後の画素を`u_u=cx+0.1fx≈730.5721 px`、`v_u=cy≈359.2825 px`とすると、視線は`q=(0.1,0,1)`になる。カメラ座標の`(0.1,0,1)`と`(0.2,0,2)`は、同じ長さ単位で表した異なる深さの点だが、この理想投影では同じ画素へ写る。これは保存値を使う計算例で、実画像の点を測定した結果ではない。

## 画像条件と校正誤差の読み方

解像度の変更・切出し・ズームなどで画素と視線の対応が変われば、以前のKを無条件には使えない。Settingsには指定した新寸法に応じて内部パラメータを調整する経路があるが、現行YAMLに`Camera.newWidth/newHeight`の指定はない。実動画との寸法一致は今回未検査である。

`Camera.RGB=0`は、3チャネルならBGR（Blue, Green, Redの順）、4チャネルならBGRA（末尾に透明度成分）の色順としてグレー化する指定。RGBはRed, Green, Blueの順を指す。`calibrate.py`の「0はグレー」というコメントを、そのまま入力形式の説明には使えない。1チャネル入力なら当該色変換枝を通らない。

RMS（Root Mean Square、二乗平均平方根）は、校正に採用した円中心の観測画素とモデルによる再投影との残差を集約する値で、単位はpxである。現行YAMLの`0.5524 px`は保存されたコメント値であり、今回再測定した値ではない。全ての点の誤差が0.5524px以下、別条件でも同じ精度、地図の誤差が0.5524m、という意味にはならない。

校正は投影の前提を整えるが、単眼の尺度・地図の累積誤差・誤対応を一度に解決する操作ではない。校正画像の条件や円の幾何情報が現物と整合しているかの評価も、今回の静的調査では行っていない。

## 理解確認

1. 現行の`mvKeysUn`は、画素座標か正規化視線か。
2. `q=(0.1,0,1)`が分かれば、点の奥行きは一意に決まるか。
3. 保存RMSが小さいことは、単眼地図のメートル尺度と位置精度を保証するか。

答えの要点：歪み補正後の画素座標／未知の深さが残る／校正観測の再投影残差の指標であり、その保証ではない。
