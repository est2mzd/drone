# D10 Atlas・地図群と共有更新

図の対応：並行図の「共有する地図群Atlas」と、DFD（Data Flow Diagram、データの流れを示す図）の「Atlas・地図群」。接続は **A06,P02,P03 ↔ P01、A20/A21、A23**。純単眼で複数の地図を保持し、担当処理が共有する構造を扱う。

## Atlasは複数のMapと現在Mapを管理する

追跡が続かなくなったとき、以前の地図を保持して別の地図を始められると、その後の観測を蓄積できる。Atlasは、このような複数のMapを管理する容器である。MapはKeyFrame（地図の代表観測、以下KF）とMapPoint（三次元地図点、以下MP）を保持する。

入力は各担当からのMap作成・切替・登録・更新の操作で、読み出し側には現在Mapや登録オブジェクトへの参照を渡す。Atlasは一つの巨大な点群配列ではなく、Mapの集合と、そのうち現在使うMapへのポインタを別々に持つ。

KF/MP自身も所属Mapへの参照を持つ。Atlas経由の`AddKeyFrame`と`AddMapPoint`は、渡されたオブジェクトの`GetMap()`を呼び、その所属Mapへ追加する。関数名だけから、常に現在Mapへ追加すると解釈しない。

## 集合と所属を区別する

現在Mapが設定され、登録が整合した安定状態を、次の概念式で表す。

\[
\mathcal A=\{M_0,\ldots,M_{r-1}\},\qquad M_{\rm cur}\in\mathcal A,
\]
\[
K\in\mathcal K_i\Rightarrow\operatorname{map}(K)=M_i,
\qquad P\in\mathcal P_i\Rightarrow\operatorname{map}(P)=M_i.
\]

| 記号 | 型・意味・前提 |
| --- | --- |
| \(\mathcal A\) | Atlasの通常Map集合`mspMaps`を表す、Map参照の有限集合 |
| \(r,i\) | rは集合の個数で整数、r≧1。iは0≦i＜rの整数の添字 |
| \(M_i,M_{\rm cur}\) | 各Mapへの参照と、現在Mapへの参照。curはcurrentの目印 |
| \(\mathcal K_i,\mathcal P_i\) | Map iに登録されたKF参照集合、MP参照集合 |
| \(K,P\) | それぞれ一つのKF、MPを指す記号。座標行列や位置ベクトルではない |
| \(\operatorname{map}(\cdot)\) | オブジェクトが保持する所属Map参照を取り出す、説明用の記法 |
| \(\in,\Rightarrow\) | 集合への所属と、「左の条件なら右の関係」という意味 |

参照・識別子・集合には長さや時間の単位はない。この式は空のAtlasやcurrent未設定を含む全状態の表現ではなく、統合・削除の途中に全フィールドが同時に切り替わる保証でもない。集合への登録と、KF/MPの`UpdateMap`による所属更新は別の操作として存在する。
## current、stored、badの意味

| 呼出し・状態 | この範囲で確認できる意味 |
| --- | --- |
| `SetCurrentMap()` | Mapの`mIsInUse=true`。Atlasのcurrentポインタ設定と組み合わせて使う |
| `SetStoredMap()` | `mIsInUse=false`。ファイルへ保存する処理ではない |
| `SetBad()` | 別のフラグ`mbBad=true`。current/storedと同じ列挙値の切替ではない |
| `Atlas::SetMapBad()` | 通常Map集合から外し、badのMap集合へ参照を移す |

新Map開始では旧Mapをstoredにし、新しいMapをcurrentにして集合へ加える。これだけで新地図の幾何が完成したり、旧地図と座標がそろったりするわけではない（A20）。現在Mapのリセットとの違いはA21を参照する。

同じAtlas内でも、未統合の各Mapはそれぞれの座標基準を持つ。純単眼では長さも任意尺度である。二つのMapに同じ数値の座標があっても、同じ物理位置を意味するとは限らない。対応を確認して座標関係を推定・適用する統合処理はP03であり、容器への登録とは別である。

## 読み出し範囲を二つのMapで確かめる

Map ID（Identifier、識別番号）が0と1の二Mapを仮定する。Map 0はstoredで2 KF・100 MP、Map 1はcurrentで3 KF・80 MPを保持し、例の読み出し中は集合が変わらないものとする。

| 呼出し | この仮定例で返る参照 |
| --- | --- |
| `Atlas::GetAllMaps()` | ID順にMap 0、Map 1への参照 |
| `Atlas::GetAllKeyFrames()` | 現在Map 1の3 KFへの参照 |
| `Atlas::GetAllMapPoints()` | 現在Map 1の80 MPへの参照。両Map合計180点ではない |
| `Map 0`の`GetAllMapPoints()` | 明示したMap 0の100 MPへの参照 |

これは実データを数えた結果ではない。80個の参照を持つvectorを返しても、80個のMP実体を複製したわけではない。Map 0の`(1,0,0)`とMap 1の`(1,0,0)`も、座標関係を確認せず同じ位置として結合できず、数値1が1mである保証もない。

## 三つの担当が同じ地図を読む・更新する

| 担当 | 共有地図との代表的な関係 |
| --- | --- |
| Tracking（P01） | 現在Mapの点・KFを用いてFrame姿勢を推定し、初期地図作成やKFの受渡しも行う |
| LocalMapping（P02） | KFや観測を登録し、新点・接続を作り、条件付き最適化で姿勢や点を更新する |
| LoopClosing（P03） | 対応する領域を検証し、姿勢・点の補正、融合、別Map間の所属移動を行う |

Trackingはwrapperの呼出しスレッド上で動き、LocalMappingとLoopClosingは別スレッドで動く（P01）。三者がそれぞれ地図の完全な独立コピーを持つという構成ではない。受渡しや参照の取得後も、同じ実体に対する更新があり得る。

ロックも一種類ではない。Atlasの`mMutexAtlas`、Mapの集合操作等に使う`mMutexMap`、複数の姿勢・点の更新区間で使う`mMutexMapUpdate`は別のmutexである。例えばTrackingは取得したcurrent Mapの更新mutexをTrack内で保持し、局所最適化の結果反映も対象Mapの更新mutexを取得する。統合では対象二Mapの更新mutexを取る区間もある。

これらは取得対象と区間を持つロックであり、Atlas全体や全オブジェクトを一括凍結するものではない。`SetMapBad`やcurrent/stored/badのsetterなど、関数内部のlockが一律でない箇所もある。全並行アクセスの安全性や、全処理の同時停止を本章の静的読解だけで保証しない。

`GetAllMaps`はMapポインタをvectorへコピーして整列し、各MapのgetterもKF/MPポインタのvectorを返す。各呼出しにロックがあることから、後で参照先から読む姿勢・位置まで同一時点で固定された、原子的な全体スナップショットとは言えない。補正結果を扱うD12や終了時保存A23でも、この範囲を越えた保証を足さない。

## 理解確認

1. Atlasの`GetAllMapPoints`は、全Mapの点をまとめて返すか。
2. storedや同Atlasへの所属は、ディスク保存・座標整列を意味するか。
3. ポインタ一覧のコピーは、参照先の姿勢・点位置を全て同じ時点に固定するか。

答えの要点：現在Mapだけ／いずれも意味しない／容器のコピーであり、全体スナップショットの保証ではない。
