# D15 姿勢・有効フラグのファイル

図の対応：DFD（Data Flow Diagram、データの流れを示す図）の「姿勢・有効フラグのファイル」と、境界図の「点・姿勢ファイル」の姿勢部分。接続は **A23 → O01,O03**。独自の`SaveCameraPoses`が内部履歴から作るファイルを扱う。

## 履歴から姿勢を再構成して出力する

D13の履歴は、参照KeyFrame（キーフレーム、以下KF）に対する相対姿勢を持つ。保存時には参照KFの現在姿勢を使って世界姿勢を再構成する。参照KFが無効化されていても、親との相対関係をたどって利用可能なKFへつなぐ経路がある。

入力はファイル名、Atlasの地図群、Trackingの相対姿勢・参照KF・時刻・lost印の4リストである。wrapperは点保存に続いて、点ファイル名のstemに`_poses.txt`を付けたパスへ呼ぶ。出力はヘッダなしの9列` t tx ty tz qx qy qz qw valid `である。

この関数は既存ローカル差分であり、固定した上流ORB-SLAM3にはない。列名やvalidの意味を、別の標準軌跡形式から推測しない。

## 地図選択と履歴の走査順

保存対象MapはD14と同じ規則で、`GetAllMapPoints().size()`が最大の候補を選ぶ。これは選別前の点参照集合の件数で、同数なら先の候補を保持し、全0なら選択先がない。ただし点保存とは**独立に選び直す**ため、二ファイルが常に同じMapを選んだとは保証できない。

選択先がない場合は、ofstreamを構築した後に0件ログでreturnし、履歴が残っていても行を書き出さない。選択先がある場合は、相対姿勢リストの先頭から履歴順に走査する。sortは行わない。

4リストのイテレータを同時に進めるが、終端を検査するのは相対姿勢リストだけである。他の3リストも同じ長さ・対応順であることを前提に使い、その検査や一括スナップショットをこの関数が行うわけではない。

各履歴が正常に走査されると、条件に不合格の履歴も含めて一行を書こうとする。D13の履歴自体が全入力画像に一対一とは限らず、前値の時刻をコピーする枝もあるため、全動画フレームに一行・時刻が常に増加という意味にはならない。

## validを決める条件

| 順序 | コード上の判定・操作 | 不合格となる場合 |
| --- | --- | --- |
| 1 | 履歴のlost印を反転して`ok`を開始 | lostがtrue |
| 2 | 採用候補の参照KFを確認 | 参照ポインタがnull |
| 3 | 参照KFがbadなら親へ進み、相対変換を蓄積 | 親がnullになり、利用可能なKFへ到達できない |
| 4 | 最後に得た非bad KFの所属Mapを選択Mapと比較 | Mapへの参照が異なる |

元の参照KFがbadというだけでは直ちに不合格にならない。親をたどって非badのKFへ到達し、所属条件も満たせば再構成へ進む。最後の比較はMapポインタの一致であり、数値ID（Identifier、識別番号）が同じかを比べる処理ではない。

ここでいうvalidは、保存時のこれらの条件を通過したかを示す。現在や画像入力当時の`Tracking OK`、数値の有限性、位置精度、全入力画像の有効性を証明するものではない。lost印の追加時とリセット時の意味もD13に従う。

## 親連鎖を通してTcwを再構成する

元の参照KFをr0、badなKFから親へたどって最初に得る非bad祖先をrmとする。必要な親関係・相対変換が利用でき、有限回でその祖先へ到達する前提で、次のように整理する。

\[
A=T_{r_0r_1}T_{r_1r_2}\cdots T_{r_{m-1}r_m},\quad A=I\ (m=0),
\qquad T_{cw}=T_{cr_0}A\,T_{r_mw}.
\]
\[
C_w=-R_{cw}^{\mathsf T}t_{cw}.
\]

| 記号 | 型・次元・座標・前提 |
| --- | --- |
| \(w,c\) | wは選択Mapの世界座標、cは対象履歴のFrameカメラ |
| \(r_0,\ldots,r_m,m\) | 元参照から最終祖先までのカメラ座標の列と、たどる辺数m。mは非負整数 |
| \(T_{ab}\) | 座標b→aの三次元剛体変換。正規直交・行列式＋1の3×3回転と三成分並進を持つ |
| \(T_{cr_0}\) | 履歴の相対姿勢。元参照カメラ→対象カメラ |
| \(T_{r_kr_{k+1}}\) | 子KFの`mTcp`に保存した親→子の変換。kは0からm−1の整数 |
| \(A,I\) | 最終祖先→元参照の合成変換と、単位変換。元参照が非badならm＝0でA＝I |
| \(T_{r_mw}\) | 保存時に読み出す最終祖先KFの世界→カメラ姿勢 |
| \(R_{cw},t_{cw},C_w\) | 再構成Tcwの3×3回転、三成分並進、世界座標での三成分カメラ中心 |
| 上付き\(\mathsf T\) | 転置。回転の転置が逆行列になることから中心を求める |

回転は無次元で、並進とカメラ中心は地図の長さ単位である。純単眼では任意尺度なのでメートルを保証しない。`parent_chain`は単位変換で始まり、各`mTcp`を右へ掛ける。式全体は右から世界→最終祖先→元参照→対象カメラの順に作用する。

`mTcp`はKFのbad化時、親がある場合に「子の世界姿勢×親の世界姿勢の逆」で保存する。親をたどる各段で、全KFの現在姿勢から差分を計算し直す処理ではない。最後の非bad祖先の現在姿勢を使うことと、この保存済み連鎖を区別する。

出力する並進は`Tcw.translation()`のtcwであり、世界内のカメラ中心Cwではない。最後の中心の式は解釈のための整理で、この保存関数がCwへ変換して書いているわけではない。

## 九列と無効行の埋め値

| 列 | 内容・単位 | 出力書式 |
| --- | --- | --- |
| `t` | 履歴のdouble時刻、秒。並進ベクトルtcwとは別 | fixedで小数点以下6桁 |
| `tx ty tz` | 世界→カメラ変換の並進三成分、地図の任意長さ単位 | valid＝1なら小数点以下9桁 |
| `qx qy qz qw` | 世界→カメラ回転のクォータニオン四成分、無次元。xyzがベクトル成分、wがスカラー成分 | `unit_quaternion()`から取得し、この順で9桁 |
| `valid` | 保存時の条件に通過なら1、不合格なら0 | 整数リテラル |

数値は姿勢型から取り出した単精度の並進・回転であり、表示9桁が九桁の測定精度を意味するわけではない。不合格行は時刻の後へ、固定文字列`0 0 0 0 0 0 1 0`を書き、次の履歴へ進む。並進ゼロ・回転の単位クォータニオンに見える部分は埋め値であり、実際のカメラ姿勢として採用しない。

## 連鎖と出力を読む小例

全回転を単位回転とし、履歴相対姿勢の並進を`(1,0,0)`、非bad親からbadな元参照へ写す`mTcp`の並進を`(2,0,0)`、親の世界→カメラ姿勢の並進を`(3,0,0)`と仮定する。合成した並進は`(6,0,0)`、世界座標のカメラ中心は`(-6,0,0)`になる。

lostがfalse、親の所属が選択Map、履歴時刻が1.2秒なら、例行は次のとおりである。

```text
1.200000 6.000000000 0.000000000 0.000000000 0.000000000 0.000000000 0.000000000 1.000000000 1
```

同じ時刻の履歴でも、保存条件に不合格なら次の埋め値行になる。いずれも実測・実保存ではない仮定例である。

```text
1.200000 0 0 0 0 0 0 1 0
```

## 保存の保証範囲とコード

時刻・並進・クォータニオンの有限性検査と、ファイルopen/writeの成否検査はない。戻り値はvoidで、末尾の`kept/total`ログは条件通過数と処理履歴数を数える。ログだけで正常書込みを証明しない。Shutdownの終了待機と共有更新の範囲もA23/D10のとおりで、全最適化完了や同時点スナップショットを保証しない。

## 理解確認

1. 元参照KFがbadなら、必ずvalid＝0になるか。
2. ファイルのtx/ty/tzは、世界座標のカメラ中心か。
3. 無効行の単位クォータニオンやvalid＝1から、何を保証してよいか。

答えの要点：親連鎖を通じて採用され得る／Tcwの並進であり中心は別／埋め値は実姿勢でなく、validは保存時条件の通過だけを表す。
