# P02 LocalMappingと非同期キュー

## 図の位置、背景と目的

並行図・データフロー図の **[LocalMapping]** に対応し、**D09のKeyFrameとD10の地図→D11の局所地図更新・D09の更新→P03**へ接続する。対象は純単眼・通常SLAMの現行`LocalMapping::Run`である。

SLAMはSimultaneous Localization and Mapping、自己位置推定と地図作成を同時に行う処理である。Trackingが画像ごとの姿勢を求める一方、LocalMappingは別スレッドで地図を増やし、観測の整合性を調整し、不要な要素を減らす。KeyFrameは地図用に残す重要画像、MapPointは三次元の地図点を指す。

入力はTrackingが待ち行列へ渡したKeyFrameと既存地図である。出力は観測・共視接続・点・姿勢を更新した局所地図と、P03へ渡すKeyFrameである。待ち行列へ入ったことと、この更新が終わったことは別である（P01）。

## 待ち行列から処理する順序

```text
KeyFrameキュー -> 先頭を取り出す/観測・接続を登録
              -> 最近の点を選別 -> 新しい点を三角測量
              -> 条件付きの近傍融合
              -> 条件付きの局所BA・KeyFrame選別
              -> LoopClosingの入口へ渡す（P03）
```

BAはBundle Adjustment、カメラ姿勢と地図点などを調整し、観測画像への再投影誤差を小さくする最適化である。上図の仕事を毎回すべて完了するとは限らず、現行`Run`には次の条件がある。

| 処理箇所 | 実行条件・途中で変わり得ること |
| --- | --- |
| 一つのKeyFrameの処理開始 | キューに要素があり、`mbBadImu`が偽。先頭要素を取り出す |
| 新点作成 | 近傍を調べる途中、最初の近傍より後で新KeyFrame到着を検出すると、その関数から戻る |
| `SearchInNeighbors` | 呼出し時にキューが空。関数内にも中断フラグによる打切り箇所がある |
| 局所BA | キューが空で停止要求がなく、さらにAtlasの現在MapのKeyFrame数が2を超える場合に呼ぶ |
| KeyFrame選別 | キューが空で停止要求がない外側条件の内側。上記の「2を超える」条件の外で呼ぶ |
| P03への受渡し | 上記のBA等を省略した場合も、処理がこの位置まで進めば`InsertKeyFrame`を呼ぶ |

純単眼では慣性センサを使う局所BAではなく、`Optimizer::LocalBundleAdjustment`の1116行から始まる関数が呼ばれる。停止要求を受けた瞬間に全処理を中止する構造ではなく、`Run`の停止枝は上のKeyFrame処理枝に入らなかった場合に評価される。

`AcceptKeyFrames()`は受付用フラグを読む。`Run`は周回の初めにfalse、処理・リセット確認の後にtrueへ設定するが、これはキューが空、あるいは全仕事が完了したという証明ではない。`InsertKeyFrame`自体はキューへ追加し、BA中断要求も立てる。受付フラグを使うTracking側の判断はA13を参照する。

新入力や停止要求は`mbAbortBA=true`を設定し得る一方、`Run`には新点作成後にfalseへ戻す箇所もある。フラグ名だけから全工程が取り消されるとは考えず、各処理がどこで確認するかを区別する。

## 観測登録、点の選別と融合

`ProcessNewKeyFrame`は専用mutex（排他ロック）の下でキュー先頭を取り出し、BoWを計算する。BoWはBag of Words、画像特徴を辞書の「語」に対応させる検索用表現である。続いて既存点の未登録観測を加え、代表記述子や観測方向等を更新し、共視接続を更新してKeyFrameをMapへ登録する。

共視とは、複数のKeyFrameが同じMapPointを観測する関係である。近傍は主にこの関係から選ぶので、地理的な距離球だけで決めるものではない。

`MapPointCulling`は最近追加された点の監視リストを対象に、発見率や観測数などで不適当な点を無効化する。一方、監視期間の条件を満たしてリストから外すだけの枝もある。監視リストから消えたすべての点が、地図から無効化されたわけではない。

`SearchInNeighbors`は現在KeyFrameの点を共視近傍へ投影し、逆向きにも近傍の点を現在画像へ照合して、重複する点の融合を試す。その後、記述子や共視接続を更新する。これは局所の観測・点の整理であり、P03の別地図どうしの統合と同じ処理ではない。

## 三角測量：既存姿勢から新しい点を作る

`CreateNewMapPoints`は、共視近傍のKeyFrameと現在KeyFrameの既存姿勢を使う。カメラ間隔と奥行の関係、対応の幾何条件、視差を調べ、三角測量後には両カメラで正の深度、再投影誤差、特徴の尺度整合などを検査する。通った点をMapPointとして作り、二つの観測を登録する。

A06は地図のない段階から二視点の姿勢と初期地図を求める。ここでは既に推定された二KeyFrameの姿勢を使い、未知の点を追加する。用いる射影関係は次の共通モデルで表せる。

\[
\mathbf u_{ij}\approx\pi_i(R_i\mathbf X_j+\mathbf t_i),\qquad
\mathbf e_{ij}=\mathbf u_{ij}-\pi_i(R_i\mathbf X_j+\mathbf t_i).
\]

\(i\)はKeyFrame、\(j\)は点を区別する整数添字で、\(\mathbf X_j\)は地図世界座標の3成分位置である。\(R_i\)は世界座標からカメラ\(i\)座標へ回す3×3回転行列（正規直交、行列式+1、無次元）、\(\mathbf t_i\)はカメラ\(i\)座標系で表す同じ変換の3成分平行移動である。点と平行移動の単位は同じ単眼地図の任意長さ単位で、メートル尺度は未確定である。

\(\mathbf u_{ij}\)は特徴点の観測位置、\(\mathbf e_{ij}\)は残差で、ともに2成分・画素単位。\(\pi_i\)は既知のカメラ校正を使い、3成分のカメラ座標から2成分の画素位置を返す投影関数である。単眼観測はコードの`mvKeysUn`に対応する。\(\approx\)は測定誤差等による近似一致を表す。

三角測量では二つの\(i\)について既知の\(R_i,\mathbf t_i\)を用い、対応した観測から\(\mathbf X_j\)を求める。十分な視差と正しい対応が必要で、上の射影式だけで悪い対応や退化を排除できるわけではない。実際の受理は先述の検査を伴う。

## 局所BA：姿勢と点を一緒に調整する

局所BAは、処理中KeyFrameと同じMapの共視KeyFrame、それらが見る点を集める。局所点を見る局所集合外のKeyFrameは固定する。また、Mapの初期KeyFrameが局所集合に含まれる場合も固定する。固定KeyFrameが0なら、この現行関数は最適化前に戻る。

動かすKeyFrameの添字集合を\(\mathcal V\)、固定する集合を\(\mathcal F\)、局所点の添字集合を\(\mathcal P\)、それらの観測対\((i,j)\)の集合を\(\mathcal E\)とする。すべて有限集合で、\(\mathcal E\)のカメラ添字は両集合を合わせた\(\mathcal V\cup\mathcal F\)から取る。目的は次のように整理できる。

\[
\min_{\{R_i,\mathbf t_i\}_{i\in\mathcal V},\{\mathbf X_j\}_{j\in\mathcal P}}
\sum_{(i,j)\in\mathcal E}
\rho_H\!\left(\mathbf e_{ij}^{\mathsf T}W_{ij}\mathbf e_{ij}\right),
\qquad W_{ij}=\sigma_{ij}^{-2}I_2.
\]

\(W_{ij}\)は2×2の逆共分散重みで単位は画素\(^{-2}\)。\(\sigma_{ij}>0\)は特徴の画像ピラミッド段に応じた標準偏差のモデル値（画素）、\(I_2\)は2×2単位行列、上付き\(\mathsf T\)は転置である。重み付き二乗誤差は無次元となる。\(\rho_H\)は大きな誤差の影響を抑えるHuber損失である。

\(\min\)は指定した姿勢と点を変数として和を小さくする目的、\(\sum\)は採用した観測対についての総和を表す。固定集合\(\mathcal F\)の姿勢とカメラ校正は変数にしない。式は同一Mapの対応観測と前方への投影が意味を持つことを前提とする。固定KeyFrameがあっても、単眼の絶対的なメートル尺度が得られるとはしない。

これは旧論文Appendix式(5)〜(7)を局所集合で整理した式で、原式の番号は付けていない。論文の2×2共分散\(\Omega\)（画素\(^2\)）に対し、本章の\(W\)はその逆行列に当たる重みである。A09の姿勢だけ最適化では点を固定したが、ここでは複数の可動姿勢と点を同時に調整する。A06の初期地図BAとも、対象集合と役割が異なる。

## 現行の反復、外れ値と中断

対象の`LocalBundleAdjustment`はHuber損失を設定し、`optimize(10)`を一回呼ぶ。これは常に10反復を完了して収束する保証ではなく、反復前の停止フラグが真なら戻り、反復中も停止フラグを最適化器へ渡している。

呼出し後は、単眼観測の重み付き二乗誤差が5.991を超えるか、深度が正でない場合に、その観測を除去対象とする。Mapの更新mutexを取ってKeyFrame側・点側の対応を外し、推定された姿勢と点位置を書き戻す。最適化中に中断して戻った場合も、この後段へ進み得るため「中断なら全結果を破棄する」とは言えない。

この関数には、さらに別の最適化を実施する二段目やHuber損失を外す処理はない。旧論文§VI-Dの途中・最後での外れ値除去や、別の同名関数の反復手順を、この現行経路へそのまま当てはめない。

例えば、可動KeyFrameが二つ、固定KeyFrameが一つあり、三者が同じ局所点を見る場合、可動側の姿勢と点位置を合わせて調整し、固定側の姿勢は保つ。観測残差が\((2,-1)\)画素、標準偏差モデルが1画素なら重み付き二乗誤差は5である。一方\((3,0)\)画素なら9となり、後段の5.991の境界を超える。これは仮定値による観測判定例で、実データの改善量を測ったものではない。

## 冗長KeyFrameの選別とP03への接続

`KeyFrameCulling`は共視KeyFrameを調べ、初期KeyFrameなどを除外して冗長なものの`SetBadFlag`を呼び、無効化を要求する。純単眼の現行条件では、ある点を他の4KeyFrame以上が`scaleLeveli<=scaleLevel+1`で観測していると冗長側へ数え、そのような点が対象点数の90%を厳密に超えた場合に判断する。KeyFrame側の保護処理もあるため、必ず即時に削除・メモリ解放するという説明にはしない。

`scaleLevel`は選別対象KeyFrameの特徴点の段番号、`scaleLeveli`は他KeyFrame側の段番号である。画像ピラミッドの段番号は大きいほど粗いため、この尺度条件は一段粗い観測も含む。旧論文とコメントにある「他の3KeyFrame」「同じか細かい尺度」を、現行の`nObs>3`や段番号比較へ読み替えず転記することはできない。

処理が末尾まで進むと、現在KeyFrameをLoopClosingの入口へ渡す。局所BAが省略・中断された場合にも、この受渡しへ進み得る。受渡しはP03側の処理完了や地図全体の最適化収束を意味しない。

## 理解確認

1. `AcceptKeyFrames()==true`は、キューが空で全更新が終了したことを保証するか。
2. A09の姿勢だけ最適化と、ここでの局所BAは、何を変数にする点が異なるか。
3. 新入力によってBAを中断したら、必ず途中結果を全部破棄するか。

答えの要点：受付フラグであり保証しない／ここでは複数の可動姿勢と点を調整し、一部の姿勢を固定する／中断後も観測選別と書戻しへ進み得る。
