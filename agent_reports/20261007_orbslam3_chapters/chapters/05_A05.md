# A05 初期地図の有無の判断

## 図の位置と背景

図Aの **<追跡に使える初期地図がある?>** に対応する。A04の特徴抽出後に入り、**いいえ→A06「複数画像から初期地図を作る」、はい→A08「現在の追跡状態は?」** へ進む。

地図があれば、現在画像を地図と照合して姿勢を求められる。開始直後は、その照合先の地図と姿勢の出発点を先に作る必要がある。したがって、初期化と通常の追跡を分ける入口が必要になる。

本章の目的は、**図の問いを、手元コードが管理する処理状態に対応させること**である。二視点から地図を求める算法や成立条件の中身はA06/A07で扱う。

## 入出力：何を調べて、どこへ進むか

| 項目 | 内容 |
| --- | --- |
| 入力 | 現在のFrameと、Trackingが保持する状態`mState`。Frameは一枚の画像の特徴・時刻などを持つ入れ物 |
| 判断に使う値 | 当該分岐へ到達した時点の`mState` |
| 初期化を要する場合 | 現行の単眼構成では`MonocularInitialization()`を呼ぶ |
| それ以外の場合 | 追跡状態に応じた処理へ進む。現在画像の追跡成功を保証する判断ではない |

Trackingは現在画像の姿勢を求める担当である。図では「初期地図があるか」と表現したが、実装のこの分岐は**状態変数の比較**であり、Atlasポインタの存在や地図点の個数を直接調べる式ではない。

## 理論と必要な式：状態を表すラベルで分岐する

`mState`は`eTrackingState`という列挙型である。列挙型とは、決められた名前から一つを選ぶ型で、ここでは処理段階を表す。

| 状態名 | 値 | 本章での意味 |
| --- | --- | --- |
| `NO_IMAGES_YET` | 0 | 初回の`Track`で未初期化へ移る前の状態 |
| `NOT_INITIALIZED` | 1 | 初期化が成立していない状態 |
| `OK` | 2 | 正常な追跡状態として管理する値。初期化成立時にもこの値になる |

表は本章で必要な状態だけを抜粋したもので、喪失等の状態も別に存在する。0・1・2は状態を識別する値であり、地図点数でも、追跡品質の点数でもない。

コードの初期化分岐を、教材用の述語として書く。

\[
B(s)=(s=\mathrm{NOT\_INITIALIZED}).
\]

\(s\)は分岐時点の状態で、型は`eTrackingState`、物理単位や空間の次元は持たない。\(B\)は状態を受け取り真/偽を返す関数、\(B(s)\)は初期化経路へ入るかを表すブール値である。右辺の等号は状態の一致判定を表す。空間座標系を扱う式ではない。

**コードの\(B(s)\)が真であることは、図の問いに対する「いいえ」に対応する。** コードは「未初期化か」を、図は「初期地図があるか」を尋ねるため、答えの向きが逆である。

前提は、現行の単眼構成で`Track`のこの分岐まで到達していることである。そこへ到達する前に`NO_IMAGES_YET`は`NOT_INITIALIZED`へ変更される。前段の異常処理による早期終了まで、この単一式で表すわけではない。

## 現行コードとの対応

確認日2026-10-07、ORB_SLAM3 HEAD `4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4`。以下のパスは`third_party/ORB_SLAM3/`基準。Tracking関連とAtlasにHEADとの差分なし。Systemは既存変更込みの手元行番号である。

| ファイル・関数・行 | 確認できる処理 |
| --- | --- |
| `include/Tracking.h:121-132`、`src/Tracking.cc:44-49` `Tracking`コンストラクタ | 状態型を定義し、`NO_IMAGES_YET`で開始 |
| `src/Tracking.cc:1862-1867` `Tracking::Track` | 初回状態を`NOT_INITIALIZED`へ変更して記録 |
| 同`:1899-1908` | 状態が`NOT_INITIALIZED`なら初期化分岐。現行単眼では`MonocularInitialization`を呼ぶ |
| 同`:1912-1925` | 呼出し後も`OK`でなければ現在Frameを保存して戻る。入口で未初期化以外なら`else`の追跡経路へ進む |
| `src/System.cc:117-137`、`src/Atlas.cc:33-37,58-76` `System` / `Atlas` / `CreateNewMap` | 保存地図を読まない起動では、初期化成立に先立ってAtlasと現在Mapの器が作られる |

初期化呼出しで状態が`OK`に変わった場合は、未成立時の`return`を通らず初期化分岐を抜ける。同じ`Track`呼出しで直後の`else`へ入り直す動作ではない。その成立の判定内容はA07へ譲る。

## 具体例：入れ物があっても、初期化へ進む

通常の新規起動では、Atlasという地図群の管理器と、現在のMapという地図の器が先に存在する。それでもTrackingの初期状態は`NO_IMAGES_YET`である。

最初の画像がこの分岐へ到達すると、状態は`NOT_INITIALIZED`へ変わる。\(B(s)\)は真なので、図の「いいえ」に沿ってA06へ進む。状態値が1であることは「地図点が1個ある」という意味ではない。入れ物の確保と、観測からの初期地図成立を分けて考える必要がある。

## 成立条件・限界と出典

この章は状態判定の入口に範囲を限る。未初期化以外の状態で追跡経路へ入っても、現在画像の追跡に成功するとは限らない。図の「はい」は初期化経路を抜けた処理段階の要約であり、実際の追跡成否は後続の判断で確かめる。

公式の[固定コミットTracking.cc](https://raw.githubusercontent.com/UZ-SLAMLab/ORB_SLAM3/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4/src/Tracking.cc)を実読し、手元の分岐と照合した。[ORB-SLAM3論文PDF](https://arxiv.org/pdf/2007.11898v2)の5頁・図1/III節も本文と画像で確認したが、論文図は地図生成を含むTrackingの役割を示すもので、この状態列挙や式を掲載しているわけではない。

調査根拠は [A05調査メモ](../research/A05_evidence.md)。実動画での状態遷移ログは採取しておらず、二視点算法や喪失後の全状態遷移も本章では調べていない。

## 理解確認

1. コードが直接比較するのは、地図点数と`mState`のどちらか。
2. \(B(s)\)が真なら、図の「はい／いいえ」のどちらへ進むか。
3. AtlasとMapが生成済みなら、初期化も成立済みと言えるか。

答えの要点：`mState`／「いいえ」からA06／器の存在だけでは成立を意味しない。
