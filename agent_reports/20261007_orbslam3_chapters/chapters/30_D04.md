# D04 事前語彙と画像検索表現

図の対応：DFD（Data Flow Diagram、データの流れを示す図）の「特徴の辞書」と、「辞書・検索用DB」の辞書部分。接続は **語彙ファイル → P01,A15,P03**。DBはDatabase（データベース）を指し、その実行中の登録・検索はD07で扱う。

ORB（Oriented FAST and Rotated BRIEF、方向を付けた特徴点と二値記述子）は、画像中の見え方を記述する。ここではその記述子を「視覚単語」にまとめ、過去のどの画像が似ているかを調べる表現へ変える。単語は「机」「窓」といった物体名ではない。

## 語彙を先に用意する目的

多数の画像の全記述子を毎回総当たりで比較すると、検索対象が増えるほど比較も増える。事前に記述子の空間を木で分けて単語番号を与え、画像を単語の集計で表せば、候補画像の検索と特徴照合の範囲を絞れる。

この変換を担うライブラリがDBoW2である。BoWはBag of Wordsの略で、画像を順序に依存しない単語の集まりとして表す方法を指す。単語の集計だけでは、画像中の配置や三次元的な整合までは確定しない。

現行`System`は`ORBvoc.txt`を`loadFromTextFile`で読み、既に作られた木・代表記述子・単語重みを復元する。その後に別の`KeyFrameDatabase`を作る。この起動経路で、入力動画から語彙を一から学習しているわけではない。

| 対象 | 保持するものと役割 |
| --- | --- |
| 事前語彙 | 木の節点・代表記述子・葉の単語番号・重み。見え方をどの単語へ割り当てるかの基準 |
| 画像のBoW表現 | その画像で各単語がどの重みで現れたか。FrameやKeyFrameが保持する検索用情報 |
| 実行中の検索DB | 登録されたKeyFrameと単語の対応を管理する別の容器。詳細はD07 |
| MapPoint | 地図中の三次元点と観測関係。同じ単語番号が同じMapPointを意味するわけではない |

## 語彙ファイルの設定と木の探索

今回確認したファイル先頭は`10 6 0 0`で、サイズは145,250,924 bytesだった。内容全体を表示・解析せず、先頭とメタデータだけを調べた。

| ヘッダの値 | 読込コードと列挙型による意味 |
| --- | --- |
| 10 | 木の分岐数パラメータ`k` |
| 6 | 木の深さパラメータ`L` |
| 最初の0 | スコア種別`L1_NORM` |
| 次の0 | 重み種別`TF_IDF` |

ヘッダは木の設定であり、実際の葉が必ず`10^6`個存在することを今回数えたわけではない。ファイルには各節点の親、葉かどうか、代表記述子、重みが保存され、葉へWordIdという単語番号を割り当てる。

```text
画像のORB記述子（1個は32 bytes＝256 bit）
    ↓ 根から各段の子の代表記述子と比較
その段で最も近い子を選ぶ → 葉へ到達 → WordIdと保存重み
    ├─ 単語ごとに重みを加算 → BowVector
    └─ 途中の節点ごとに画像内の特徴番号を記録 → FeatureVector
```

比較に使うHamming距離は、二つの256bit記述子で異なるbitの数である。現行`FORB::distance`はbitの排他的論理和を数える。木では各段の子の中から近いものを選んで下るため、全葉を比較した厳密な最近傍と必ず一致するとは限らない。

このように多数の異なる記述子を、代表値を持つ単語へまとめて割り当てる操作を量子化と呼ぶ。異なる特徴が同じ単語へ入るため、単語の一致をそのまま幾何的な対応の成立としない。

## TF-IDFの集約とL1正規化

TFはTerm Frequency（その画像内の単語の出現頻度）、IDFはInverse Document Frequency（多数の学習画像に共通する語を弱める重み）である。現行の変換は、語へ割り当てた記述子ごとに**保存重みが正なら加算**し、最後にL1正規化する。

有限な保存重みを前提に、一画像Aの処理を次のように整理できる。これは実装の整理式であり、論文の式番号を付けた転載ではない。

\[
a_i^A=\begin{cases}n_i^Aw_i & w_i>0,\\0 & w_i\le0,\end{cases}
\qquad Z_A=\sum_i a_i^A,\qquad
v_i^A=\frac{a_i^A}{Z_A}\quad(Z_A>0).
\]

| 記号 | 型・単位・意味 |
| --- | --- |
| A、後述のB | 比較する二つの画像のラベル。座標系のラベルではない |
| i | 語彙中のWordIdを走る整数の添字。和は語彙の全単語について取る |
| \(n_i^A\) | 画像Aの記述子が語iへ割り当てられた回数。非負整数、単位は個数 |
| \(w_i\) | 語iの葉から読み出す保存重み。式では有限な実数、無次元 |
| \(a_i^A\) | 正の保存重みだけを集約した非負実数値。無次元 |
| \(Z_A\) | 集約値の総和である非負実数の正規化係数。無次元 |
| \(v_i^A\) | 正規化後の語iの成分。非負実数、無次元。\(Z_A>0\)なら全成分の和は1 |

非出現語の成分は0である。概念上は語彙全体に対するベクトルだが、`BowVector`の実体はWordIdから重みへの疎な表で、必要な成分だけを持つ。画像の特徴点数と、この表に現れる単語数は同じとは限らない。

学習側の関数はIDFを`ln(N/N_i)`で計算する。`ln`は自然対数、Nは訓練画像の総数、N_iはその語が一度以上現れる訓練画像数で、正の整数かつ`1≤N_i≤N`。比と重みは無次元である。これは重みの意味を示すもので、現行起動時は保存値を読み、訓練集合やNを再計算しない。今回、その実訓練集合・重みの再現性は確認していない。

記述子がない場合や、正の重みへ寄与する特徴がない場合、BowVectorは空になり得る。`Z_A=0`へ上の割算を適用しない。実装もノルムが正の場合だけ割り、空の表の成分和を1とはしない。

## 画像の似かたを数値にする

二つとも非空・非負でL1正規化されたベクトルの場合、現行`L1Scoring`は次の形で説明できる。

\[
s(A,B)=1-\frac12\sum_i|v_i^A-v_i^B|
      =\sum_i\min(v_i^A,v_i^B)\in[0,1].
\]

\(s\)は無次元の類似度、\(v_i^B\)はBについて同じ方法で作った成分、縦棒は絶対値、`min`は小さい方の値を取る操作である。各成分の差の絶対値の和をL1距離と呼ぶ。同じ重み分布なら1、共通する正の成分がなければ0となる。

説明用に二語の保存重みを`(1,2)`と仮定する。Aの出現数が`(2,1)`、Bが`(1,2)`なら、集約値はAが`(2,2)`、Bが`(1,4)`、正規化後はAが`(0.5,0.5)`、Bが`(0.2,0.8)`となる。

このとき共通部分の重みは`min(0.5,0.2)+min(0.5,0.8)=0.7`で、距離の式からも同じ値を得る。これは仮定した小例で、実語彙の重みを測定した結果ではない。スコア0.7を姿勢の確率や正しい場所である確率とも解釈しない。

どちらかが空のとき、実装は共通語の寄与がなく0を返す。両方が空でも、正規化済みという前提の上式へ代入して類似度1とはしない。検索候補の後に対応・姿勢を確かめる処理はA15/P03を参照する。

## FeatureVectorは画像内の特徴へ戻る索引

`FeatureVector`は木のNodeIdから、その節点に入った**画像内の特徴番号の列**への表である。番号は記述子行のインデックスで、三次元点番号でもBoWの重みでもない。現行変換では、保存重みが正の特徴だけがこちらにも登録される。

`Frame::ComputeBoW`と`KeyFrame::ComputeBoW`は`transform(...,4)`を呼ぶ。この4は`levelsup`で、実装の目標段は`L-levelsup`、今回のL=6なら根を0とした深さ2である。「根から4段目」の指定ではなく、ここでは全葉の深さ分布を測定したともしていない。

`ORBmatcher::SearchByBoW`は両画像で同じ節点に入った特徴同士へ比較を絞り、その中で記述子の対応を調べる。葉の単語による画像検索と、より上の節点による特徴照合の候補制限を、同じ役割としない。

FrameはBoWが空なら、KeyFrameはBoWまたはFeatureVectorが空なら記述子から変換する。KeyFrame生成時にはFrameの記述子・両表を引き継ぐ経路もある。画像ごとの表を作ることと、共有する語彙木を再学習することは別である。

## 理解確認

1. 新しい画像のBoWを計算するとき、語彙木も毎回一から学習するか。
2. `transform(...,4)`は、今回の木で根から何段目をFeatureVectorの目標にするか。
3. 両方が空のBoWに、正規化済みベクトルの式を当てはめて類似度1としてよいか。

答えの要点：保存語彙を使って変換する／根を0とする深さ2／前提を満たさず、現行スコアは0となる。
