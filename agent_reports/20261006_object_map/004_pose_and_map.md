# 自己位置と地図の関係

欲しいのはリアルタイムの自己位置である。その前に、オフラインで地図を作る。地図を作るときの観測と、リアルタイムの観測が違うと、同じ場所を同じものとして照合できない。

点群は地図にしない。重いし、リアルタイムの検出箱と形が違う。地図は YAML で、物体は位置とサイズ、壁や床は大きい平面として置く。

## 一つの観測を、両方に使う

毎フレーム出すものを観測と呼ぶ。オフラインもリアルタイムも、この観測だけを入出力にする。

```
映像
  → 観測（箱、揃った深度、支持平面、広い面）
      → オフライン: 姿勢が付いた観測を、世界の YAML へ積む
      → リアルタイム: 姿勢が未知の観測を、その YAML と照合してカメラ姿勢を解く
```

オフラインが積むものと、リアルタイムが探すものは同じ項目である。クラス、位置、サイズ、面の法線。点群や、別モデルの姿勢を混ぜると、照合の単位がずれる。

姿勢の初期値が要るのはオフラインの蓄積だけである。そこにも ORB-SLAM3 は使わない。精度が足りなかった方式を、物体地図の座標の出所にすると、また観測が二つになる。深度を出したのと同じ呼び出しから姿勢の初期値を取り、物体と面の照合で直す。

## 動画の4面は、観測の候補が違う

4面は別々の動画ではない。1フレームの中で、地図に何を残すかの候補を並べている。背景は黒で、残したものだけが見える。

| 面 | 残すもの | 地図での意味 | この映像で起きたこと |
| --- | --- | --- | --- |
| 1 箱だけ | 検出した矩形 | 画像上の位置しか無い。奥行きが無いので、世界の位置にもサイズにもならない | 矩形は出る。それだけでは地図の点にできない |
| 2 深度が揃った所 | 箱の中で深度が揃った画素 | 物体の候補。位置は相対深度、サイズは画素の広がり | 99件中96件が通る。クラスが間違っても、面が平らなら残る |
| 3 支持平面 | 水平に近い面 | 床や机。物体を載せる台。Liao らは、この面を除いた残りを物体にする | 28フレーム中7フレームにしか無い。無い面は真っ黒になる |
| 4 広い面 | 画面の大きな面 | 壁や床。Kimera が構造と呼ぶもの。仮の大きい平面として置き、あとでサイズを入れる | 全フレームにある。Mini 3 では画面の大半が一つの面になり、壁一枚には分かれていない |

面3が真っ黒なのは失敗ではなく、そのフレームに水平な台が無い、という結果である。面4が画面のほとんどを塗るのは、相対深度がなだらかだと、壁と家具が一つの面に潰れている、という結果である。

## 自己位置は、まだ解いていない

いまできているのは、1フレームの観測を動画で見ることまでである。カメラ姿勢も、世界の YAML も、まだ書いていない。

次に書く地図の1件は、この形にする。

```yaml
objects:
  - class: chair
    position_xyz: [x, y, z]
    size_xyz: [w, h, d]
planes:
  - kind: wall
    normal_xyz: [x, y, z]
    offset: d
    size_xy: [w, h]  # 最初は仮の大きい値
```

`position_xyz` は、観測2の揃った深度を、そのフレームの姿勢で世界へ移したものである。`planes` は観測4を移したものである。観測3があるフレームでは、物体がどの面の上に乗っているかを同じ YAML に足す。

リアルタイムの自己位置は、新しいフレームの観測2と観測4を、この `objects` と `planes` へ対応づけ、カメラの姿勢を解く。入力の形は、オフラインで地図を積んだときと同じにする。
