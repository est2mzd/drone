# 物体の位置とサイズで室内地図を作る計画

大監督者。2026-10-06。指示は `user_directions/20261005_object_detection.md`。

## 読んだ条件

ORB-SLAM3 も Depth Anything 3 単体も、自己位置の精度が足りない。欲しいのはリアルタイムの自己位置で、その前にオフラインで地図を作る。地図を作るときとリアルタイムで方式が違うと、同じ場所を同じ観測として扱えない。

仮説は次のとおり。

- 物体検出で箱を取る。
- 箱の内側で、一定以上の面積（まず 50%）の深度が揃っていれば、その画素はその物体に属する。
- 点群の地図は重い。
- 世界地図は YAML に位置とサイズを書く。
- 壁のような大きいものは、まず大きい平面として置き、精度が上がってからサイズを入れる。

## 近い技術と、取るところ

| 技術 | 取るところ | 取らないところ |
| --- | --- | --- |
| QuadricSLAM（Nicholson ら, 2019） | 検出箱がセンサで、ランドマークは物体の位置と大きさ。点を地図にしない | 双対二次曲面そのもの。箱だけでは視点が揃うまで大きさが決まらない |
| RGB-D Object SLAM Using Quadrics（Sensors, 2020） | 1枚の深度で物体の大きさを決める。箱の中の点を全部は使わず、物体に属する点を選ぶ | 楕円体の最適化。支持平面の推定は後の段 |
| CubeSLAM（Yang, Scherer, 2019） | 1つの箱から直方体の大きさを出したい、という目的 | 消失点。室内の下り映像で消失点が弱いと、第1段の成否がそれに引っ張られる |
| Kimera / Hydra のシーングラフ | 家具（object）と壁・床（structure）を分け、どちらも姿勢と大きさで持つ | TSDF、メッシュ、場所グラフ。点群に近い重さになり、検出箱とは別の地図になる |
| Depth Anything 3 | 単眼の相対深度。既存の `overlay.py` と同じ `DA3-SMALL`、長辺 504、1枚ずつ | 多視点をまとめて深度と姿勢を出す呼び方。オフラインだけそうすると、リアルタイムの1枚推論と深度の意味がずれる |

第1段の深度はメートルにしない。`DA3-SMALL` の出力は相対深度である。メートルは `DA3METRIC-LARGE` の `metric = focal * depth / 300` で後から合わせる。いまの PC は CPU だけで、大きいモデルは第1段の問いと別である。

外部の実装はクローンしない。取るのは観測の形だけなので、`third_party/` には置かない。室内映像はクローンではなく取得データなので `object_map/videos/` に置き、Git には入れない。

## 積み上げ

各段は、前の段のファイルを入力にする。方式は観測 YAML のまま増やす。

| 段 | やること | これで分かること | 残る資産 |
| --- | --- | --- | --- |
| 1 | 1フレーム。箱の内側で深度が揃う割合を測り、50% 以上を採用する | 室内でこの規則が物体を残すか、背景の混ざった箱を落とすか | `object_observation_v1` と `object_map/extract_objects.py`。リアルタイムも同じ YAML を出す |
| 2 | 隣り合うフレームで、同じクラスかつ画像上で重なる箱をつなぐ | 採用した物体がフレームをまたいで残るか。単フレームの偶然か | トラック。まだ世界座標ではない |
| 3 | 検出に出ない広い面（壁、床）を、同じ深度の一致で `kind: plane` として足す。サイズは仮の大きい値 | 家具だけでは地図が空でないか | 平面の項目。仮説の「壁は大きい平面」 |
| 4 | キーフレームの姿勢も同じ DA3 の1枚呼び出しから取り、トラックを1つの YAML へ融合する | 相対深度のまま位置とサイズが安定するか。スケールが別途要るか | `world_map`。位置とサイズ。点群は置かない |
| 5 | 新しいフレームの観測を `world_map` の物体へ対応づけ、カメラ姿勢を解く | 点群なしで自己位置が追えるか。オフラインとリアルタイムの観測が同じか | 自己位置。入力は段1の YAML |

段4の姿勢に ORB-SLAM3 は使わない。精度が足りなかった方式を、物体地図の座標の出所にすると、また方式が二つになる。物体の対応で姿勢を補正するのは段5で、段4の初期値は深度と同じモデルから出す。

## 第1段の承認

小監督者は段1だけを作業にする。世界座標、平面、トラック、自己位置は段1のスクリプトに入れない。

完了は次で判断する。

- 合成深度の検査が通る。
- Mini 3 の保存映像と、ネットの室内映像およそ10本から、各2フレームの YAML と重ね画像がある。
- クラスごとに、検出数、採用数、深度一致割合の中央値が出ている。
- 採用の理由が `agree`、不採用が `depth_split` / `small_box` / `empty_depth` で分かれている。

この結果を見て段2に進む。大半が `agree` なら 50% は緩い。大半が `depth_split` なら、縁の背景か、相対深度のばらつきが原因である。その切り分けが段1の成果で、段2の作業計画はそこから書く。
